# A1 Search Monitor

Автономный сервис контроля видимости объявлений A1 на первых трёх страницах
поиска Auto.ru и Avito без API этих площадок и без зависимости от локального
компьютера в целевой production-конфигурации.

Рабочая папка проекта: `/Users/filaret/Desktop/a1_search_monitor_noapi_product`.

## Что решает продукт

- импортирует актуальный реестр автомобилей из Google Sheets по публичному CSV-export;
- распознаёт прямые ссылки Auto.ru и Avito независимо от физической позиции столбцов;
- не разрушает последнюю рабочую версию при изменении структуры таблицы подрядчиком;
- проверяет страницы 1–3 один раз на фильтр и сопоставляет все ожидаемые объявления;
- сохраняет страницу и позицию каждого найденного объявления;
- отделяет подтверждённый непоказ от CAPTCHA, HTTP-ошибки и поломки парсера;
- ведёт историю эпизодов, включая пересечение с субботой и воскресеньем;
- показывает отчёт, состояние расписания, импортов и площадок;
- принимает замечания менеджеров и ведёт аудит их обработки;
- собирает кандидатов ссылок из публичных кабинетов дилера, но не угадывает VIN;
- ежедневно резервирует PostgreSQL и проверяет восстановление отдельной командой.

## Архитектура

```text
Google Sheets CSV export
        │
        ▼
защищённый импорт ──► PostgreSQL ◄── обратная связь менеджеров
        │                 │
        │                 ├── реестр фильтров и ожиданий
        │                 ├── append-only наблюдения
        │                 ├── эпизоды непоказа
        │                 └── журнал изменений ссылок
        ▼
планировщик ──► Playwright-адаптеры ──► страницы 1–3
        │                    │
        │                    └── скриншоты доказательств
        ▼
HTML-отчёт + JSON API + operational status
```

Контейнеры: `app`, `db`, `backup`; в облачном override добавляется `caddy` для
автоматического HTTPS. Изменения схемы выполняются Alembic-миграциями.

Проверено 4 сентября 2026 года:

- реальный импорт: 130 строк, 106 валидных, 24 диагностических;
- в реестре 34 активных автомобиля, 78 ссылок Auto.ru и 76 ссылок Avito;
- unit/integration suite: 46 тестов;
- stage smoke включает readiness, импорт, отчёт, миграцию, loopback-порты,
  backup и изолированный restore;
- восстановление подтвердило совпадение количества объявлений и снимков;
- локальный stage работает в профиле `local_vpn`, поэтому живые результаты
  площадок не считаются доказательством production-доступности без VPN;
- автоматические живые обходы в локальном stage отключены.

Production ещё не объявлен готовым: нужны целевой сервер и домен, no-VPN
проверка обеих площадок, утверждённые поисковые URL и 14-дневный пилот.
Подробности: `docs/RELEASE_STATUS.md`.

## Быстрый запуск локального stage

```bash
cd /Users/filaret/Desktop/a1_search_monitor_noapi_product
cp .env.example .env
```

Для локального stage установите как минимум:

```dotenv
APP_ENV=stage
NETWORK_PROFILE=local_vpn
AUTH_ENABLED=false
DB_PASSWORD=<локальный URL-safe пароль>
DEALER_DISCOVERY_ENABLED=false
```

Затем:

```bash
./scripts/deploy.sh
./scripts/smoke_stage.sh
```

Отчёт по умолчанию: `http://127.0.0.1:8000/api/v1/dashboard`.
В текущем локальном `.env` используется порт `18000`.

## Облачный запуск

Production-развёртывание не должно выполняться через VPN. Нужны Linux VPS,
Docker/Compose, DNS-имя и открытые входящие 80/443.

1. Скопировать `.env.example` в `.env` и задать уникальные секреты.
2. Оставить `NETWORK_PROFILE=unknown` до фактической проверки маршрута.
3. Указать `DOMAIN`, включить `AUTH_ENABLED=true`.
4. Развернуть:

```bash
docker-compose \
  -f docker-compose.yml \
  -f deploy/cloud/docker-compose.cloud.yml \
  up -d --build
```

5. Проверить исходящий маршрут без VPN, импорт и тестовые обращения к площадкам.
6. Только после этого установить `NETWORK_PROFILE=cloud_no_vpn` и
   `APP_ENV=production`. Иначе приложение намеренно откажется стартовать.

Точный порядок и stop-rules описаны в `INSTRUCTION.md` и `docs/RUNBOOK.md`.

## Настройка поисковых фильтров

В исходном листе «Анализ_Размещения» поля J:M сейчас не содержат утверждённых
поисковых URL. Система не пытается изобрести бизнес-фильтры и до их добавления
показывает `not_configured`.

Фильтр можно добавить в отчёте или через `POST /api/v1/filters`:

```json
{
  "source": "auto_ru",
  "name": "V-Class Москва",
  "url": "https://auto.ru/moskva/cars/mercedes/v_klasse/used/",
  "apply_to_all_active": true,
  "vins": []
}
```

URL должен быть страницей поисковой выдачи, а не карточкой A1, объявлением или
кабинетом дилера. Назначение «весь активный сток» автоматически обновляется
после каждого импорта.

## Основные endpoints

- `GET /api/v1/health` — liveness;
- `GET /api/v1/ready` — БД, окружение и auth;
- `GET /api/v1/system/status` — свежесть цикла и причины деградации;
- `GET /api/v1/dashboard` — рабочий HTML-отчёт;
- `POST /api/v1/import` — импорт источника;
- `POST /api/v1/scan` — только проверка выдачи;
- `POST /api/v1/cycle` — импорт, актуализация ожиданий, discovery и scan;
- `GET|POST|PATCH /api/v1/filters` — реестр фильтров;
- `GET|PATCH /api/v1/listings` — объявления и подтверждённые правки ссылок;
- `GET|POST|PATCH /api/v1/feedback` — обращения менеджеров;
- `POST /api/v1/dealer/discover` — ручной обход кабинетов;
- `GET /api/v1/dealer/candidates` — найденные кандидаты ссылок;
- `GET /api/v1/dashboard/weekends` — выходные дни и инциденты.

Кроме `/health` и `/ready`, production endpoints защищаются Basic Auth поверх HTTPS.

## Критические правила

1. Один валидный непоказ — `absent_uncertain`; второй подряд —
   `absent_confirmed` и открытый эпизод.
2. Неполный обход, CAPTCHA, 429, неизвестная разметка или отсутствующая прямая
   ссылка — техническое состояние, а не непоказ.
3. Наблюдение через VPN не смешивается с production без VPN.
4. Ссылка из кабинета не связывается с VIN автоматически без надёжного ключа.
5. История не переписывается; правки и статусы аудируются.

## Обязательное действие по безопасности до production

В ранее использовавшемся файле `SCRIPT.py` были обнаружены жёстко записанные
учётные данные GitHub и DeepSeek, а сам Drive-файл имел публичное право записи.
Значения здесь намеренно не приводятся. До production владелец должен:

1. отозвать/перевыпустить оба ключа;
2. удалить секреты из файла и истории доступных копий;
3. убрать публичное право записи и оставить минимально необходимый доступ;
4. подтвердить ротацию отдельной проверкой.

Продукт не меняет права Google Drive и не отзывает внешние ключи автоматически.
