# A1 Search Monitor — инструкция по запуску и эксплуатации

Документ предназначен для владельца продукта, администратора сервера и
менеджеров, которые проверяют объявления.

## 1. Роли

- **Owner** утверждает поисковые фильтры, пользователей, правила реакции и релиз.
- **Administrator** разворачивает сервис, хранит секреты, следит за backup и health.
- **Manager** подтверждает ссылки, создаёт замечания и проверяет исправления.
- **Contractor** поддерживает исходную таблицу, но не получает автоматического
  права изменять внутреннюю историю мониторинга.

## 3. Подготовка production без VPN

Требования: Linux VPS, Docker с Compose, домен, DNS A/AAAA, входящие TCP 80/443,
исходящий HTTPS без VPN.

### 3.1 Секреты и конфигурация

Создайте `.env` из примера. Задайте:

```dotenv
APP_ENV=stage
NETWORK_PROFILE=unknown
AUTH_ENABLED=true
ADMIN_USERNAME=<не admin>
ADMIN_PASSWORD=<минимум 16 случайных символов>
DB_PASSWORD=<минимум 32 URL-safe случайных символа>
DOMAIN=monitor.example.ru
DEALER_DISCOVERY_ENABLED=false
```

`DB_PASSWORD` должен быть URL-safe, поскольку он входит в DSN приложения.
Файл `.env` — `chmod 600`, он не коммитится.

### 3.2 Первый deploy

```bash
docker-compose \
  -f docker-compose.yml \
  -f deploy/cloud/docker-compose.cloud.yml \
  up -d --build
```

Caddy получает TLS-сертификат автоматически. Проверить:

```bash
curl https://monitor.example.ru/api/v1/health
curl https://monitor.example.ru/api/v1/ready
```

`health` и `ready` публичны; остальные endpoints требуют Basic Auth.

### 3.3 No-VPN gate

До объявления production:

1. На сервере подтвердить отсутствие VPN/proxy-туннеля.
2. Выполнить `POST /api/v1/import` и сверить 130/106/24 с текущим эталоном;
   отличия допустимы только при фактическом изменении таблицы.
3. Добавить по одному контрольному фильтру Auto.ru и Avito.
4. Запустить `POST /api/v1/scan`.
5. Сверить страницы/позиции с ручным открытием той же выдачи.
6. Включить dealer discovery и проверить `POST /api/v1/dealer/discover`.
7. Убедиться, что CAPTCHA/429 отражаются как technical, а не absence.

Только после успешной проверки установить:

```dotenv
APP_ENV=production
NETWORK_PROFILE=cloud_no_vpn
DEALER_DISCOVERY_ENABLED=true
```

Production с другим профилем намеренно не стартует.

## 4. Настройка фильтров

Фильтры — бизнес-вход, их нельзя угадывать из названия автомобиля. Добавьте URL
через форму «Добавить или обновить фильтр» либо API.

Варианты назначения:

- конкретный список VIN;
- «всем активным авто с объявлением на площадке».

Второй вариант динамический: новые активные автомобили добавляются после
импорта, выбывшие исключаются. Прямая карточка объявления, сайт A1 или dealer URL
не принимаются как поисковый фильтр.

До утверждения фильтров `/api/v1/system/status` показывает `not_configured`, а
система не делает выводов о видимости.

## 5. Ежедневный цикл

Планировщик выполняет:

1. удаление просроченных скриншотов по retention;
2. импорт Google Sheets;
3. синхронизацию динамических ожиданий;
4. обход кабинетов дилера, если он включён;
5. проверку активных фильтров страниц 1–3;
6. запись наблюдений и обновление эпизодов.

Ручной запуск из контейнера:

```bash
docker-compose exec -T app python -m app.cli run-cycle
```

Параллельный scan/discovery блокируется, чтобы не создавать двойные наблюдения.

## 6. Как читать статусы

- `found` — карточка найдена; номер страницы и позиция сохранены отдельно.
- `absent_uncertain` — первый валидный непоказ; тревога ещё не открыта.
- `absent_confirmed` — второй и последующий валидный непоказ подряд.
- `technical_error` — вывод невозможен: сеть, CAPTCHA, 429, неизвестная разметка,
  неполный обход или нет валидной прямой ссылки.

Эпизод открывается на втором валидном непоказе, но его начало равно времени
первого. Первое последующее `found` закрывает эпизод. Technical-событие не
увеличивает серию и не закрывает эпизод.

## 7. Ссылки объявлений

Основной источник — поля `AUTO-RU` и `AVITO-RU` в импортируемом листе. Если ссылка
отсутствует:

1. открыть раздел «Кандидаты из кабинетов дилера»;
2. проверить карточку вручную;
3. выбрать автомобиль, площадку и URL;
4. указать имя проверившего и основание;
5. сохранить.

Система создаёт `ListingLinkEvent`. Неподтверждённый кандидат не меняет реестр.
При отсутствии VIN на публичной странице нельзя подтверждать связь только по
похожей цене или названию.

## 8. Обратная связь менеджеров

Форма «Сообщить об ошибке» принимает категорию, критичность, автомобиль и текст.
API: `GET|POST|PATCH /api/v1/feedback`.

Допустимые переходы:

```text
new -> checking | assigned
checking -> assigned | fixed
assigned -> checking | fixed
fixed -> checking | confirmed
confirmed -> terminal
```

Изменения пишутся в `FeedbackEvent`. Исправление на площадке подтверждается
отдельно; тикет не переписывает прошлое наблюдение.

## 9. Изменение таблицы подрядчиком

Безопасно: перестановка столбцов, дополнительные поля и известные алиасы.

Опасно: исчезновение поля идентичности, резкое падение числа валидных строк,
несколько VIN в ячейке или неоднозначные дубли. Такой импорт карантинируется либо
строки исключаются с диагностикой. Последний рабочий реестр сохраняется.

Диагностика: последний импорт на dashboard и данные `SourceImportSnapshot` /
`ImportFieldDrift` в БД. Полный контракт — `docs/DATA_CONTRACT.md`.

## 10. Backup и восстановление

Контейнер `backup` немедленно создаёт первый архив, затем повторяет операцию раз
в сутки. По умолчанию retention — 14 дней.

```bash
./scripts/backup_now.sh
./scripts/restore_test.sh
```

Restore-test создаёт отдельную временную БД, восстанавливает последний dump,
сравнивает контрольные количества и удаляет только эту временную БД.

Перед обновлением production обязательно выполнить обе команды.

## 11. Обновление и откат

1. Создать и проверить backup.
2. Зафиксировать текущий commit/image.
3. Запустить тесты и `./scripts/deploy.sh` на stage.
4. Применить Alembic-миграции через штатный startup.
5. Проверить `/ready`, `/system/status`, dashboard и логи.
6. При дефекте вернуться к известному commit/image; если схема несовместима —
   восстановить проверенный backup. Не выполнять ручной destructive downgrade.

## 12. Инциденты

### Просрочен цикл

`/system/status` показывает `overdue` после интервала плюс допуска. Проверить
контейнер app, scheduler, доступ к Google Sheets и время последнего `ScanRun`.

### Массовый technical_error

Не принимать рекламных решений. Проверить сетевой профиль, HTTP-коды, evidence и
изменение DOM. Исправить адаптер на fixture, затем выполнить контрольный прогон.

### Массовый confirmed absence

Сначала убедиться, что нет общего изменения фильтра/ссылок. Сверить ручную
выборку. Только после этого передавать бизнес-инцидент ответственному.

### Карантин импорта

Не отключать защиту и не снижать порог вслепую. Сопоставить новые заголовки с
контрактом, добавить тест и только затем обновлять маппинг.

## 13. Обязательная безопасность

До production отозвать обнаруженные ранее GitHub/DeepSeek credentials из
`SCRIPT.py`, удалить их из доступных копий и убрать публичное право записи на
Drive-файл. Сервис сам эти внешние изменения не выполняет.
