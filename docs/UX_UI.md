# UX/UI: рабочее место мониторинга

Главный сценарий: обзор → проблемное размещение → история автомобиля → замечание
менеджеру → подтверждение исправления. Каждый этап доступен из левой навигации.

Обзор отвечает на четыре вопроса: сколько автомобилей, какие размещения найдены,
где требуется повторная проверка, сколько замечаний открыто. Настройка URL и
техническая диагностика вынесены в отдельную страницу.

Размещения используют табличный вид для сравнения результатов; автомобили — карточки
для узнавания машины. Все активные автомобили и несопоставленные активные строки
головной таблицы помещаются на одну страницу. Карточка показывает внешний вид,
цену с разделением тысяч, VIN или пометку об его отсутствии, год, статус/наличие,
НДС и две независимые проверки каждой площадки: страницу поисковой выдачи и
состояние прямого URL. История автомобиля сохраняет доказательства, изменения
реестра и замечания. Снимок не подменяется произвольной фотографией; при наличии
снимка прямой карточки он имеет приоритет над превью поисковой выдачи.

Состояния: найдено / повторный непоказ / нужен повтор / техническая ошибка /
нет фильтра / нет актуальной проверки. Текст сохраняется вместе с цветом.
Раздел «Сверка ссылок» показывает актуальность ID в каталоге продавца отдельно
от видимости в поиске. Кандидат выбирается человеком с указанием основания;
сходство модели и цены не является автоматическим подтверждением автомобиля.

Прогресс включает обновление таблицы, сверку продавца, фильтр, страницу, паузу,
последовательную проверку прямых карточек `N/всего` и итог; старый heartbeat
отдельно обозначается. Прошлый успешный запуск не означает работающую сейчас программу.

Визуальная система: тёмная боковая навигация, светлый рабочий фон, зелёный акцент,
янтарный для необходимости проверки, красный для повторного непоказа. Статические
ресурсы локальные. Общая типографика, доступный keyboard focus, подписи полей,
адаптивные карточки; широкие таблицы прокручиваются внутри своей области на телефоне.

Действия запуска не имитируются кнопкой Web: управление Chrome запускает локальный
.command. Во время скана видны реальное окно браузера и журнал.
