# A1 Search Monitor — инструкция по запуску и эксплуатации

Актуальная версия: 0.9.0. Краткий ежедневный запуск — в README; новые разделы
интерфейса описаны в конце этой инструкции. Окружение: docs/LOCAL_ENVIRONMENT.md.

Перед поисковым мониторингом автоматически запускается «Сверка ссылок»: сначала
каталоги продавца, затем сопоставление текущих ID и только потом поисковые фильтры.
Если ссылка устарела, откройте этот раздел, сравните кандидатов с машиной и
подтвердите правильную публикацию. При следующем запуске она будет сверена снова.
При CAPTCHA устраните проблему вручную и перезапустите обычный локальный цикл.
Проверка не пытается автоматически решать CAPTCHA и не считает блокировку непоказом.

У VLE утверждён новый group-фильтр и ссылка владельца. Для долгосрочного
сопоставления нужно заполнить VIN либо стабильный ID автомобиля в источнике.

Документ предназначен для владельца продукта, администратора сервера и
менеджеров, которые проверяют объявления.

## 1. Роли

- **Owner** утверждает поисковые фильтры, пользователей, правила реакции и релиз.
- **Administrator** разворачивает сервис, хранит секреты, следит за backup и health.
- **Manager** подтверждает ссылки, создаёт замечания и проверяет исправления.
- **Contractor** поддерживает исходную таблицу, но не получает автоматического
  права изменять внутреннюю историю мониторинга.

## 2.1 MSI / Windows 11

Целевой рабочий компьютер — MSI с Windows 11, Intel Core Ultra 5 125U и 16 ГБ RAM.
Откройте PowerShell в папке репозитория и выполните:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\setup_windows.ps1
.\scripts\start_windows.ps1 -OpenDashboard
```

`setup_windows.ps1` создаёт `.venv312`, устанавливает `requirements.lock`,
готовит `.env`, поднимает Docker Compose и проверяет `/api/v1/ready`. Скрипт не
открывает площадки. Нужны Docker Desktop с WSL2 backend, Git for Windows,
Python 3.12 и Google Chrome.

Рабочая проверка на MSI:

```powershell
.\scripts\local_scan_windows.ps1 -Engines auto_ru,avito -Pages 3 -Pace cautious
```

Для расписания после завершения предыдущего цикла:

```powershell
.\scripts\local_scan_windows.ps1 -Watch -IntervalMinutes 360 -Pace cautious
```

VPN должен быть отключён для Auto.ru и Avito. Chrome открывается в отдельном
профиле `artifacts\local_chrome_profile`. Ошибка `2` означает частичный прогон
или технические ошибки и требует просмотра dashboard, а не трактовки как полного
успеха.

Публичный HTML-отчёт формируется после завершения прогона:

```powershell
.\scripts\publish_pages.ps1
```

Команда только создаёт `public/`. Явная отправка в GitHub выполняется флагом
`-Push`; Bitrix получает ссылку отдельной командой после настройки входящего
webhook. Полный порядок описан в `docs/LOCAL_ENVIRONMENT.md`.

## 3. Реальный локальный мониторинг

Требования: macOS с Google Chrome, запущенный Docker Desktop, отсутствие VPN для
Avito/Auto.ru и активная пользовательская сессия.

### 3.1 Первый запуск Chrome-профиля

Программа использует отдельный профиль `artifacts/local_chrome_profile`. Он не
смешивается с личным профилем Chrome и не попадает в git или backup.

```bash
./scripts/local_scan.sh --pages 1 --probe-url 'https://www.avito.ru/brands/a1auto/items/all/avtomobili?s=profile_search_show_all&sellerId=e4036231f69cc5cfc365db2f79600230'
```

Если Avito показывает кнопку «Продолжить», проверку проходит пользователь в
открывшемся окне. Программа CAPTCHA не нажимает и не решает. После успешной
страницы повторите probe: ожидается `LOCAL_PROBE_OK`.

### 3.2 Полный рабочий прогон

```bash
./scripts/local_scan.sh --engines avito --pages 3 --pace cautious
./scripts/local_scan.sh --engines auto_ru,avito --pages 3 --pace cautious
./scripts/local_scan.sh --watch --interval-minutes 360 --pace cautious
```

Команда сама поднимает PostgreSQL и backup, подключается к видимому Chrome и
пишет наблюдения с профилем `local_browser`. В терминале сразу отображаются
текущая площадка, фильтр, страница, количество распознанных карточек и целевых
снимков. Dashboard показывает тот же ход проверки и обновляется раз в секунду:
`http://127.0.0.1:18000/api/v1/dashboard`. Итог обязательно печатается в
терминал. Код возврата `0` означает полный технический проход, `2` — частичный
прогон/technical error, `1` — ошибка локальной конфигурации.

Перед каждым обходом площадок, а также перед каждым повтором `--watch`, worker
обязательно обновляет реестр `Monitoring` из настроенного Google Sheets CSV-export.
В терминале должны появиться строки `РЕЕСТР · обновление Monitoring` и
`LOCAL_SOURCE_REFRESH_OK`. Обновляются прямые ссылки объявлений, в том числе
заменённые подрядчиком ссылки VLE 300, затем пересчитываются связи с фильтрами.
Если источник недоступен или импорт помещён в карантин из-за изменения структуры,
обход Auto.ru/Avito не запускается и последний рабочий реестр не перезаписывается.

`cautious` — рабочий режим по умолчанию. Он делает случайную паузу 12–20 секунд
перед каждым фильтром, 6–12 секунд перед каждой страницей и ждёт полную
отрисовку выдачи. Ожидаемая длительность браузерной части с прямыми карточками —
примерно 20–40 минут, но защита площадки и число ссылок могут увеличить время.
Паузы видны в терминале и dashboard. Режим `--pace normal` оставлен только для
короткой диагностики. Щадящий темп снижает нагрузку, но не является обходом
SmartCaptcha и не гарантирует, что площадка не запросит подтверждение.

Окно отдельного Chrome автоматически выводится на передний план. Не закрывайте
его последнюю вкладку во время проверки; если все вкладки были закрыты до старта,
worker создаст новую. Если вкладка была закрыта во время загрузки, система один
раз повторит этот же фильтр через 5 секунд и покажет событие в терминале и
dashboard. При CAPTCHA текущий цикл не продолжает фильтр автоматически:
пройдите проверку пользователя и повторите команду.

Для короткой выдачи Auto.ru worker читает показанный площадкой счётчик
предложений. Если, например, на первой странице распознаны все `2 предложения`,
это считается доказанным концом выдачи: страницы 2–3 не запрашиваются, чтобы не
попасть на служебную страницу модели вместо результатов поиска.

Режим `--watch` повторяет цикл через заданный интервал, в том числе по выходным.
Терминал, компьютер и пользовательская сессия должны оставаться активными.

```bash
curl -fsS http://127.0.0.1:18000/api/v1/status/scans/latest | python3 -m json.tool
```

Не запускайте `docker-compose exec app ... scan` как рабочий способ: контейнерный
headless-браузер блокируется Avito. Endpoint web-контейнера оставлен закрытым
профилем `local_vpn`, чтобы случайный вызов не создал ложные наблюдения.

## 4. Настройка фильтров

Основной набор фильтров хранится независимо от таблицы подрядчика в каноническом
каталоге. Версия `a1-monitoring-rules-2026-09-07-v4` собирает утверждённый
файл «Инструкция по мониторингу машин.md» и уточнение owner от 07.09.2026. Импорт
автоматически синхронизирует:

- 10 фильтров Auto.ru;
- 6 уникальных поисковых сценариев Avito;
- связи с автомобилями по площадке, семейству модели и `new/used/all`.

Для всех канонических фильтров Auto.ru обязательна только Москва без расширения
радиуса: `geo_radius=0&rid=213`. Для новых V-Class дополнительно обязателен общий
список: `output_type=list`. Уточнение отменяет ошибочную трактовку +200 км.
Для всех шести канонических фильтров Avito также обязательны только Москва и
радиус 0 км: путь `/moskva/` и `localPriority=0&radius=0&searchRadius=0`.
Поиск по всей России (`/all/`) больше не используется в этих фильтрах.
Сохранённые в Chrome настройки не заменяют параметры утверждённого URL.
Во время контрольного прогона отдельно подтвердите отображаемую площадкой
географию; успешное сохранение URL не доказывает, что площадка его применила.
Перед фильтрами и страницами worker выдерживает случайные щадящие паузы; после
загрузки Auto.ru дополнительно ждёт `AUTO_RU_PAGE_DELAY_SECONDS`. При CAPTCHA
остальные фильтры площадки не открываются, а помечаются как technical error до
ручного подтверждения.

Проверить покрытие:

```bash
curl http://127.0.0.1:18000/api/v1/filters/catalog/status | python3 -m json.tool
```

Поле `unmatched` — не техническая мелочь, а очередь бизнес-настройки. Сейчас в
исходной инструкции нет URL Avito для V-Class, поэтому эти объявления не должны
участвовать в скане Avito до утверждения фильтра. Два указанных URL Sprinter
считаются одной выдачей и не дублируют статистику.

Ручной фильтр можно добавить через форму «Добавить или обновить фильтр» либо API.
Каталог не перезаписывает ручное отключение существующего фильтра.

Варианты назначения:

- конкретный список VIN;
- «всем активным авто с объявлением на площадке».

Второй вариант динамический: новые активные автомобили добавляются после
импорта, выбывшие исключаются. Прямая карточка объявления, сайт A1 или dealer URL
не принимаются как поисковый фильтр.

Если для площадки нет ни одного активного фильтра, `/api/v1/system/status`
показывает `not_configured`, а система не делает выводов о видимости.

## 5. Ежедневный цикл

Полный рабочий цикл выполняет:

1. обновление Google Sheets-реестра `Monitoring`;
2. синхронизацию динамических ожиданий;
3. сверку актуальных ID с кабинетами продавца;
4. проверку активных фильтров страниц 1–3;
5. последовательное открытие всех валидных прямых карточек;
6. запись наблюдений, причин снятия и обновление эпизодов;
7. сверку с головной таблицей, Hermes и независимый аудит Ouroboros.

Прямые карточки открываются после поисковых фильтров, чтобы возможная CAPTCHA на
длинной проверке описаний не лишала систему результатов выдачи. Первая блокировка
останавливает остальные прямые обращения к этой площадке и фиксируется как
техническая неопределённость.

Ручной рабочий запуск:

```bash
./scripts/local_scan.sh --engines auto_ru,avito --pages 3
```

Параллельный scan/discovery блокируется, чтобы не создавать двойные наблюдения.

## 6. Как читать статусы

- `found` — карточка найдена; номер страницы и позиция сохранены отдельно.
- `absent_uncertain` — первый валидный непоказ; тревога ещё не открыта.
- `absent_confirmed` — второй и последующий валидный непоказ подряд.
- `technical_error` — вывод невозможен: сеть, CAPTCHA, 429, неизвестная разметка,
  неполный обход или нет валидной прямой ссылки.

Production-эпизод открывается на втором валидном непоказе `local_browser`, но его
начало равно времени первого. Первое последующее `found` в том же production-
контуре закрывает эпизод. Серии разных сетевых профилей не смешиваются.
Technical-событие не увеличивает серию и не закрывает эпизод. Диагностический
`local_no_vpn` не открывает бизнес-эпизоды; `local_vpn|unknown` не запускаются.

В каталоге объявлений ссылки имеют вид `Auto.ru · стр. 2` и `Avito · стр. 1`.
Страница рассчитывается отдельно по последнему достоверному обнаружению на каждой
площадке. `стр. —` означает, что прямая ссылка есть, но подтверждённого обнаружения
ещё нет. Ниже отдельно показано состояние прямой карточки: работает, продано,
снято, закрыто, перенаправлено или не проверено. Если прямой снимок доступен, он
является основным превью; иначе используется снимок конкретной карточки из выдачи.

В интерфейсе доступны четыре уровня:

1. `/api/v1/dashboard` — управленческая сводка;
2. `/api/v1/dashboard/listings` — карточки автомобилей с прямыми ссылками;
3. `/api/v1/dashboard/history` — история с фильтрами и доказательствами.
4. `/api/v1/dashboard/feedback` — очередь замечаний и подтверждение исправлений.

Клик по автомобилю открывает его историю, эпизоды отсутствия и форму замечания,
привязанную к конкретному наблюдению. Превью — это сохранённый снимок выдачи на
момент скана; если его нет, интерфейс так и сообщает.

## 7. Ссылки объявлений

Основной источник — поля `AUTO-RU` и `AVITO-RU` в импортируемом листе. Если ссылка
отсутствует:

1. открыть раздел «Кандидаты из кабинетов дилера»;
2. проверить карточку вручную;
3. выбрать автомобиль, площадку и URL;
4. указать имя проверившего и основание;
5. сохранить.

Система создаёт `ListingLinkEvent`. Неподтверждённый кандидат не меняет реестр.
При отсутствии VIN на публичной странице нельзя подтверждать связь только по
похожей цене или названию.

## 8. Обратная связь менеджеров

Форма «Сообщить о неточности» в карточке автомобиля привязывает обращение к
конкретному наблюдению. Экран `/api/v1/dashboard/feedback` показывает очередь,
приоритет, ответственного и полный журнал переходов; там же ответственный меняет
статус. API: `GET|POST|PATCH /api/v1/feedback`.

Допустимые переходы:

```text
new -> checking | assigned
checking -> assigned | fixed
assigned -> checking | fixed
fixed -> checking | confirmed
confirmed -> terminal
```

Для `assigned` обязателен ответственный. Переход в `confirmed` требует имени
проверившего и комментария с результатом контрольной проверки. Изменения пишутся
в `FeedbackEvent`. Исправление на площадке подтверждается отдельно; тикет не
переписывает прошлое наблюдение.

## 9. Изменение таблицы подрядчиком

Безопасно: перестановка столбцов, дополнительные поля и известные алиасы.

Опасно: исчезновение поля идентичности, резкое падение числа валидных строк,
несколько VIN в ячейке или неоднозначные дубли. Такой импорт карантинируется либо
строки исключаются с диагностикой. Последний рабочий реестр сохраняется.

Диагностика: последний импорт на dashboard и данные `SourceImportSnapshot` /
`ImportFieldDrift` в БД. Полный контракт — `docs/DATA_CONTRACT.md`.

## 10. Backup и восстановление

Контейнер `backup` немедленно создаёт первый архив, затем повторяет операцию раз
в сутки. По умолчанию retention — 14 дней.

```bash
./scripts/backup_now.sh
./scripts/restore_test.sh
```

Restore-test создаёт отдельную временную БД, восстанавливает последний dump,
сравнивает контрольные количества и удаляет только эту временную БД.

Перед обновлением production обязательно выполнить обе команды.

## 11. Обновление и откат

1. Создать и проверить backup.
2. Зафиксировать текущий commit/image.
3. Запустить тесты и `./scripts/deploy.sh` на stage.
4. Применить Alembic-миграции через штатный startup.
5. Проверить `/ready`, `/system/status`, dashboard и логи.
6. При дефекте вернуться к известному commit/image; если схема несовместима —
   восстановить проверенный backup. Не выполнять ручной destructive downgrade.

## 12. Инциденты

### Просрочен цикл

`/system/status` показывает `overdue` после интервала плюс допуска. Проверить
контейнер app, scheduler, доступ к Google Sheets и время последнего `ScanRun`.

### Массовый technical_error

Не принимать рекламных решений. Проверить сетевой профиль, HTTP-коды, evidence и
изменение DOM. Исправить адаптер на fixture, затем выполнить контрольный прогон.

### Массовый confirmed absence

Сначала убедиться, что нет общего изменения фильтра/ссылок. Сверить ручную
выборку. Только после этого передавать бизнес-инцидент ответственному.

### Карантин импорта

Не отключать защиту и не снижать порог вслепую. Сопоставить новые заголовки с
контрактом, добавить тест и только затем обновлять маппинг.

## 13. Обязательная безопасность

До production отозвать обнаруженные ранее GitHub/DeepSeek credentials из
`SCRIPT.py`, удалить их из доступных копий и убрать публичное право записи на
Drive-файл. Сервис сам эти внешние изменения не выполняет.

   Перед обходом обновляется локальный реестр из опубликованного источника.

Разделы: «Обзор», «Автомобили», «Размещения», «Статистика», «История»,
«Замечания», «Активность», «Настройки». Цена и карточка автомобиля находятся
в «Автомобилях»; результаты по каждой площадке и фильтру — в «Размещениях».
В статистике выбирается период 7/30/90 дней. Технический сбой не означает непоказ.
В «Активности» видны импорты, изменения реестра, проверки и работа с замечаниями.

Первичная установка: `./scripts/setup.sh`. Проверка окружения без обхода
площадок: `make doctor`. История кода — `CHANGELOG.md` и Git, не автокоммиты.

Далее сохранён подробный регламент мониторинга. Настройка окружения вынесена
в `docs/LOCAL_ENVIRONMENT.md`, определения статистики — в `docs/METRICS.md`.
