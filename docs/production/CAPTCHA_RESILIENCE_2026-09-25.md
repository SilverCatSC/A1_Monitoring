# CAPTCHA и блокировка IP: диагностика и план устойчивой проверки

Статус: причина **не устранена**. Этот документ отделяет подтверждённые факты
от гипотез и задаёт критерии, после которых цикл можно считать полным.
Владелец разрешил остановку для ручного прохождения интерактивной CAPTCHA,
но предпочитает автономное завершение, когда оно возможно без обхода защиты.

## Analyse: выводы и гипотезы

Факт: одиночный refresh не решил интерактивную CAPTCHA Auto.ru. Гипотеза:
накопление посещений или серия новых анонимных контекстов повысили вероятность
challenge; это не доказано. «Ленивая» отрисовка изображений не устраняет
серверное решение о CAPTCHA и повредила бы доказательства карточек.

Факт: Avito отказал сразу с сообщением о проблеме IP. Гипотеза: фактический
egress или репутация адреса, а не число запросов этого цикла. Нужно отдельно
проверить маршрут браузера, не выключая VPSUS и не делая серию запросов к
Avito. Повторная попытка с тем же невыясненным IP не считается решением.

Автономное снижение риска (одна браузерная сессия в пределах источника,
умеренная частота, отсутствие повторного открытия уже доказанной карточки)
может уменьшить число challenge, но не гарантирует доступ: решение о CAPTCHA
принимает площадка. Для Auto.ru есть [официальный API](https://yandex.ru/dev/autoru/doc/ru/),
но [доступ требует токена дилера](https://yandex.ru/dev/autoru/doc/ru/concepts/access).
API потенциально заменит часть проверки собственного инвентаря при согласии
компании и площадки; он сам по себе не докажет позицию объявления в публичной
выдаче. Использование API не принято как текущая зависимость проекта.

## Write down → Task: контракт исправления

1. **Ни одной молча пропущенной проверки.** Для каждого ожидаемого сочетания
   автомобиль/площадка/фильтр/карточка сохранять проверено либо ожидает
   доступа, с причиной и доказательством. CAPTCHA, HTTP 429 и непройденная
   страница не дают `FOUND`, `ABSENT_CONFIRMED` или «объявление продано».
   Пока есть ожидающие, итог не может быть `completed`.
2. **Не откладывать текущие карточки за поисковую CAPTCHA.** Эксперимент
   M7.18 с отложенным открытием текущих ID отключён: если поиск блокируется,
   поздняя карточка не открывается. До отдельной приёмки все доступные
   ID-карточки вновь проверяются до поиска. Снижение нагрузки допустимо только
   как дозирование тех же проверок без потери покрытия.
3. **Интерактивная CAPTCHA Auto.ru.** Следующая архитектурная задача — один
   временный приватный контекст на площадку в пределах цикла, видимый
   challenge, пауза для штатного прохождения человеком по уже полученному
   согласию владельца,
   проверка возврата на требуемую страницу и продолжение с неё. Контекст
   закрывается после цикла, cookies между циклами не сохраняются. Нельзя
   автоматически нажимать/решать CAPTCHA либо считать закрытие окна успехом.
   Обычная повторная загрузка может устранить лишь временный сбой; при
   повторном интерактивном challenge автономное завершение не гарантируется.
4. **Avito HTTP 429.** Отдельно подтвердить фактический внешний маршрут
   браузера и доступ с выбранной политикой VPSUS; при необходимости решить
   вопрос штатным способом с сетью/площадкой. Не менять VPN наугад, не
   использовать прокси, чужие cookies или серию быстрых повторов.
5. **Продолжение.** Текущий `retry-cycle` создаёт новый полный цикл, а не
   продолжает незавершённые пункты. До production-приёмки нужен долговечный
   список ожидающих проверок и resume именно этих пунктов с новым временем и
   доказательством, сохраняя неизменяемую историю исходного цикла.

Порядок реализации: сначала учёт всех pending и тест остановки, затем
одноразовый контекст и контролируемая пауза/продолжение Auto.ru, отдельно
проверка egress и восстановление доступа Avito, затем один live gate. Пока
первые три задачи не выполнены, повторный полный цикл не служит тестом
«устойчивости к CAPTCHA».

## Критерии приёмки

- Unit/integration: CAPTCHA на странице N сохраняет N и все непроверенные
  задания; после разрешения той же сессии проверка продолжается с N без
  ложных статусов. Неуспешное разрешение оставляет задания pending.
- HTTP 429 на первом каталоге не запускает повторный шквал и оставляет все
  задания Avito pending; Auto.ru учитывается независимо.
- Приватность: одноразовый контекст не сохраняется между циклами; ручное
  прохождение, если разрешено владельцем, работает внутри одного цикла.
- Live gate: полный контролируемый проход Auto.ru и Avito с подтверждённым
  маршрутом, без pending и без технических пропусков. Пока gate не выполнен,
  вывод «полная проверка проведена» запрещён.
