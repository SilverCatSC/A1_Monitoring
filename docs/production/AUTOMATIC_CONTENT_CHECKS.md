# Проверка содержания карточек

Каждый следующий этап сверки публикаций формирует `automatic_content_checks`
в неизменяемом отчёте цикла. Раздел показывается в dashboard; журнал выводит
число проверенных карточек и карточек с предупреждениями.

Проверка сопоставляет только доступные поля внутри одной активной карточки:
год заголовка/характеристик/описания, явную цену описания и основную цену,
точный пробег характеристик/описания, отдельно заданные условия НДС и описание.
Выделяются общий шаблон, отсутствие/неподтверждённая полнота описания и тип
силовой установки, ошибочно названный комплектацией.

Заводская комплектация и индивидуальное переоборудование салона не приравниваются.
Альтернативные цены с НДС и без НДС не считаются автоматически противоречием.
Неизвестное значение не становится нулём или положительным результатом.

Коллектор отдельно сохраняет `year_title`, `year_attribute`, `mileage_km`,
`mileage_raw`, `owners_raw`, `owners_count`, `owners_minimum`, `factory_equipment`,
`vat_attribute` и источники параметров. «4 и более» — нижняя граница, а не точное
число владельцев; «50 тыс. км» не превращается в 50 км. Параметры описаний,
рекомендаций и явно скрытых элементов не подменяют характеристики карточки.

Этот слой не сопоставляет объявления по VIN/цене и не присваивает unique_id.
Отсутствие внутренних противоречий не подтверждает соответствие документам
или текущей таблице маркетинга. Сверка с оригинальной таблицей по подтверждённому
unique_id остаётся отдельной проверкой. Источники и отметки времени сохраняются.

Для уже сохранённого цикла результаты можно пересчитать по архивным HTML/JSON
без новых запросов площадкам. Такое уточнение отмечается как разбор сохранённых
материалов, привязывается к SHA256 и не перезаписывает исходные доказательства.

## Автоматическая сверка с оригинальной книгой

После внутренних проверок `PlacementCycleService.run` вызывает
`add_marketing_comparison`. Во время чтения трёх листов фидов читает также
`Размещение_автомобилей` оригинальной настроенной книги через существующий CSV-export.
Снимок содержит SHA256 каждого листа, URL книги и начало/конец чтения. Это четыре
последовательных чтения, а не атомарный снимок одной ревизии Google Sheets.
Если основной лист недоступен или изменились ожидаемые заголовки, сверка с ним
показывается как недоступная; успешное чтение фидов сохраняется.

Связь: точный валидный `placement_id` сохранённой карточки → единственная строка
соответствующего фида (`autoru-feed-all.unique_id` или `Id` обоих Avito-листов)
→ единственный VIN этой строки → единственная строка основного листа со статусом
«Актуально», содержащая этот VIN как полный токен в K. VIN самой карточки,
цена, модель и URL в назначении идентификатора не участвуют. Кириллические
визуальные подстановки автоматически не исправляются. Неоднозначная связь
остаётся открытой; пустая W/X не исключает строку из проверки содержания.

Сравниваются цена L, год M, пробег N, НДС P, пакет А1 J, полные описания листа
фида и карточки; дополнительно сравнивается точное число владельцев O, если
оно прочитано в обоих источниках. Заводская комплектация не заменяет пакет А1.
Отличие полного текста — повод для проверки, а не доказанная ошибка: оформление
и маскирование VIN тоже меняют текст. Недостающие параметры остаются неизвестными.
Расхождения «карточка — основной лист» и «лист фида — основной лист» различаются.
Фактически подключённый XML не проверяется. Каждая связь и параметр имеют точные
адреса ячеек. Таблица остаётся read-only.

Существующий цикл уточняется отдельным hash-bound файлом `content_review`, без
изменения оригинального отчёта, статуса цикла и доказательств. Даты архивных
карточек показываются отдельно от даты текущего чтения книги.

### Уточнение чтения ID по полным сохранённым описаниям

`content_identity.resolve_content_identity` различает точное чтение, восстановление
из полного текста, визуальный кириллический вариант и ранее явное подтверждение
владельца. Исходные поля карточки не изменяются, способ связи сохраняется в
`identity_resolution`, а подтверждённый ID отображается в дополнении отчёта.

Для визуального варианта разрешены только известные похожие буквы первых четырёх
символов. Цифры не меняются. Проверяются все помеченные ID в полном описании:
противоречивые/повреждённые значения не выбираются автоматически. Нужны SHA256
полного текста, целый снимок с manifest соответствующего URL, единственный ASCII
ID в актуальном фиде и такой же ID в описании фида. Заполненный `AvitoId` должен
совпадать с номером карточки и не дублироваться. Пустой `AvitoId` не заменяется
догадкой: связь тогда опирается на текстовый ID и единственную строку фида.
Смешанные буквы сохранённого DOM не доказывают ошибку исходного фида или маркетинга.

Если ID в описании отсутствует, `AvitoId` сам по себе его не назначает. Допускается
только уже существующее явное подтверждение владельца, повторно проверенное
`confirmed_operator_id`, с актуальным ID/AvitoId фида и целыми доказательствами.
Для прочих карточек остаётся открытая неопределённость.

Если VIN строки Avito-фида пуст, после независимого подтверждения unique_id
допускается связь **строк внутри книги** по единственному AvitoId фида и номеру
объявления в X основного листа. Требуется единственная строка «Актуально».
Это основание `workbook_avito_id` помечается отдельно; повреждённый или неоднозначный
VIN так не обходится. VIN публикации, цена и модель никогда не назначают ID.
