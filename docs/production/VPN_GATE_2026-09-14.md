# VPSUS split-tunnel verification — 2026-09-14

## Scope

Read-only verification on the current Mac. VPN settings were not changed,
reconnected or exported. No CAPTCHA bypass, login, marketplace scan or account
operation was performed.

## Historical configuration observation

- The PacketTunnel extension is running and utun4 is UP with tunnel address
  10.0.0.2.
- The macOS default route is handled by utun4.
- At the earlier visible-app check, VPSUS showed direct-routing mode for the
  exact exceptions avito.ru and auto.ru. In this mode the two marketplace
  domains are intended to bypass VPN while other traffic uses the active tunnel.
- The active ChatGPT/Codex session continued to exchange messages during the
  verification.

## Current read-only routing audit

- VPSUS is connected as a PacketTunnel; `utun4` is UP and handles the macOS
  default route.
- Current DNS addresses for chatgpt.com, auto.ru and www.avito.ru resolve to
  routes through `utun4`.
- Fresh unauthenticated HTTPS reached Auto.ru and Avito with HTTP 200.
  ChatGPT returned HTTP 403 after TLS, which is an application response rather
  than a transport failure.
- The active VPSUS binary configuration is opaque and the Mac was locked, so the
  current UI rules could not be inspected. Internal PacketTunnel/Xray routing
  may still make domain decisions, but the system route alone cannot prove it.

## Controlled availability evidence

- A normal Chrome tab for Auto.ru was already loaded with a vehicle-search
  title, without a network-error screen.
- One unauthenticated HTTPS request returned HTTP 200 for auto.ru.
- One unauthenticated HTTPS request returned HTTP 200 for www.avito.ru.
- chatgpt.com returned HTTP 403 to a non-browser HEAD request. This is an
  application-layer response after the TLS connection, not evidence of a route
  failure; the active ChatGPT session is the relevant functional evidence.

## Assessment and limitation

The current Mac meets the tunnel-connected and domain-reachability part of the
gate. It does **not** currently prove that Auto.ru and Avito leave directly,
because their browser egress rule inside the live PacketTunnel cannot be read
while the Mac is locked. The historical direct-rule observation is useful, but
not a substitute after the active binary configuration changed.

To close the split-routing fact, unlock the Mac, capture the VPSUS rule screen
read-only, and perform one controlled browser-level check for ChatGPT, Auto.ru
and Avito without CAPTCHA bypass or a VPN reconnect. CAPTCHA, 401, 403, 429,
timeout or a changed page remain technical results, never a reason to weaken
the VPN or bypass platform protection.

This record closes neither the direct-browser routing check nor M7. The current
MacBook scope still requires the controlled shadow-run outcome and owner
acceptance; if owner enables a schedule, it also requires a separate per-user
LaunchAgent trigger gate. MSI/Windows repetition is a fallback-only procedure,
not a current MacBook release requirement.
