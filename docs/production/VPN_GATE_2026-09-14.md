# VPSUS split-tunnel verification — 2026-09-14

## Scope

Read-only verification on the current Mac. VPN settings were not changed,
reconnected or exported. No CAPTCHA bypass, login, marketplace scan or account
operation was performed.

## Configuration evidence

- The PacketTunnel extension is running and utun4 is UP with tunnel address
  10.0.0.2.
- The macOS default route is handled by utun4.
- VPSUS shows direct-routing mode for the exact exceptions avito.ru and auto.ru.
  In this mode the two marketplace domains are intended to bypass VPN while
  other traffic uses the active tunnel.
- The active ChatGPT/Codex session continued to exchange messages during the
  verification.

## Controlled availability evidence

- A normal Chrome tab for Auto.ru was already loaded with a vehicle-search
  title, without a network-error screen.
- One unauthenticated HTTPS request returned HTTP 200 for auto.ru.
- One unauthenticated HTTPS request returned HTTP 200 for www.avito.ru.
- chatgpt.com returned HTTP 403 to a non-browser HEAD request. This is an
  application-layer response after the TLS connection, not evidence of a route
  failure; the active ChatGPT session is the relevant functional evidence.

## Assessment and limitation

The current Mac meets the intended split-tunnel configuration and basic
reachability gate: ChatGPT remains connected through the active tunnel, while
Auto.ru and Avito are configured for direct access and returned successful
unauthenticated HTTPS responses. This does not prove every browser feature or
future marketplace availability. CAPTCHA, 401, 403, 429, timeout or a changed
page remain technical results, never a reason to weaken the VPN or bypass
platform protection.

This record closes only the current Mac VPN routing check. M7 still requires a
controlled shadow-run, MSI/Windows repetition and owner acceptance.
