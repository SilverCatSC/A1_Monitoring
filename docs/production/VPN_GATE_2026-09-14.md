## Current read-only routing audit

- VPSUS is connected as a PacketTunnel; `utun4` is UP and handles the macOS
  default route.
- Current DNS addresses for chatgpt.com, auto.ru and www.avito.ru resolve to
  routes through `utun4`.
- `chatgpt.com` and `auto.ru` also expose IPv6 addresses. The current macOS
  state has multiple IPv6 `utun` defaults without an attributable VPSUS route,
  so the browser's IPv6 path is not proven by the IPv4 observation.
- Fresh unauthenticated HTTPS reached Auto.ru and Avito with HTTP 200.
  ChatGPT returned HTTP 403 after TLS, which is an application response rather
  than a transport failure.
- The active VPSUS binary configuration is opaque to the available macOS
  automation: its UI exposes only the PacketTunnel extension rather than a
  readable rule screen. Internal PacketTunnel/Xray routing may still make domain
  decisions, but the system route alone cannot prove it.

## Follow-up UI and dual-stack reachability evidence

After the MacBook was manually unlocked, a read-only inspection of the running
VPSUS wrapper showed the current exceptions as `avito.ru` and `auto.ru` under
the heading `Напрямую`. The visible client description says this mode bypasses
VPN and uses the ordinary internet connection. VPSUS remained connected for the
inspection; no exception was added, removed or changed and no reconnect was
performed.

Fresh unauthenticated HTTPS probes, with no cookies or account session, reached
all three services in both address families:

| Family | chatgpt.com | auto.ru | www.avito.ru |
| --- | --- | --- | --- |
| IPv4 | HTTP 403 after TLS | HTTP 200 | HTTP 200 |
| IPv6 | HTTP 403 after TLS | HTTP 200 | HTTP 200 |

This replaces the earlier lack of IPv6 reachability evidence. It confirms that
the live setup simultaneously reaches the three services over IPv4 and IPv6
while VPSUS is connected, and that the two marketplace domains currently have
an explicit direct-mode rule. It still does **not** expose a per-domain public
egress IP: the PacketTunnel may make its decision internally, so neither a
system default route nor an HTTP response alone is a cryptographic attribution
of the physical path.

With the VPSUS connection left active, an ordinary Chrome session visibly loaded
ChatGPT, Auto.ru, and an Avito page whose address bar showed the canonical

screenshot is retained in this record. The observation did not change VPSUS
configuration, reconnect the VPN, register or run a scheduler, or start a

This is functional evidence that the three services were simultaneously usable
in the normal browser session while VPSUS was connected. It does **not** reveal

## Required policy declaration

The functional requirement is simultaneous access, but it does not by itself
select a split-routing policy. The current UI evidence establishes that Auto.ru
and Avito have direct-mode exceptions; it does not itself adopt this as the
owner's policy or determine the intended ChatGPT route. Before this gate can
close, the owner must record one intended path for each service — `VPN exit` or
`direct physical connection` — including required subdomains and both IP
families.

## Assessment and limitation

The current Mac now has tunnel-connected, dual-stack domain-reachability,
ordinary-browser functional-access and readable direct-rule evidence for the
two marketplace domains. This does **not** prove a public egress IP for either
marketplace: their final browser egress rule may still be applied inside the
live PacketTunnel. The owner policy declaration and its independent evidence
remain necessary before a full cycle.

To close the split-routing fact, record the intended policy and perform one
controlled browser-level check for ChatGPT, Auto.ru and Avito without CAPTCHA
bypass or a VPN reconnect. The declared policy and proof must cover IPv4 and
IPv6. CAPTCHA, 401, 403, 429, timeout or a changed page remain technical
results, never a reason to weaken the VPN or bypass platform protection.

This record closes neither the direct-browser routing check nor M7. The current
MacBook scope still requires the controlled shadow-run outcome and owner
acceptance; if owner enables a schedule, it also requires a separate per-user
LaunchAgent trigger gate. MSI/Windows repetition is a fallback-only procedure,
not a current MacBook release requirement.
