# Локальная проверка перед сдачей

`scripts/check_saved_monitoring.py` повторно обрабатывает сохранённый отчёт,
снимки и, при указании, локальную копию книги. Не обращается к площадкам,
Google Sheets или базе, не создаёт цикл и не меняет исходные файлы.

```sh
cd /Users/filaret/Desktop/Monitoring
PYTHONPATH=src:. .venv312/bin/python scripts/check_saved_monitoring.py \
  --report artifacts/evidence/cycles/4be1cce3-f3cd-4b0f-b63b-c5fcb8cccad0/placement_reconciliation.json \
  --evidence-dir artifacts/evidence \
  --search artifacts/evidence/cycles/4be1cce3-f3cd-4b0f-b63b-c5fcb8cccad0/search_collection.json \
  --snapshot artifacts/marketing_site_audit_20261021/snapshot.json \
  --output artifacts/offline_checks/review.json
```

Результат: JSON с подробностями и соседний HTML для человека.
Код возврата 0 означает, что проверенные сохранённые данные прошли проверки
целостности. Код 2 означает проблему данных или запуска. Ни один из кодов не
означает, что выполнен новый живой прогон или проект готов к эксплуатации.
Бизнес-расхождения не подменяют техническую целостность: они перечислены отдельно.

Проверяются:

- SHA256 снимка и принадлежность доказательства площадке, URL и этапу прямого
  чтения. HTTP 200 требуется для активной карточки; явное снятие допускает также
  404/410. Неизвестное перенаправление остаётся неподтверждённым.
- Полный сохранённый текст, SHA256 и признак отсутствия программного обрезания.
- Противоречивые наблюдения одного номера объявления.
- Пересчёт внутренних расхождений и, при наличии снимка книги, связей по unique_id.
  VIN применяется для связи строк внутри книги; цена не назначает идентификатор.
- Сохранённые позиции только из коллекции того же цикла. Чужая коллекция отклоняется.
- Неизменность исходных JSON до/после обработки; их SHA256 записаны в результате.

Отдельно показываются полнота перечисления каталога и чтения карточек. Отсутствие
описаний в старом формате не восстанавливается догадкой. Снимок книги от 21 октября
не называется актуальной таблицей на дату пересчёта. Исторические бизнес-замечания
могли быть устранены позднее; их нельзя отправлять маркетингу как новые без проверки.

## Подтверждённые исправления 23 октября

1. Снимок другого объявления/поиска/CAPTCHA не подтверждает содержание карточки
   и exact unique_id при проверке сохранённых данных с каталогом доказательств.
2. Противоречивые состояния или unique_id одной ссылки не выбираются порядком
   записей и не превращаются в подтверждённое исчезновение/перевыкладку.
3. Видимая кнопка с прежней надписью после раскрытия описания больше не вызывает
   бесконечное ожидание её исчезновения. Ожидание реального раскрытия остаётся
   без тайм-аута; готовность содержания проверяется следующим этапом коллектора.

## Что ещё требуется для приёмки

Локальные тесты и повторная обработка архивов не подтверждают работу на текущей
вёрстке площадок. До сдачи нужен согласованный контрольный живой прогон обеих
площадок с актуальной книгой и ручным прохождением CAPTCHA, проверкой полноты
каждого каталога/фильтра, чтения карточек и сохранения отчёта. Неустановленный
unique_id должен остаться открытым вопросом, а неполное покрытие — явным результатом.
Причины снятия/блокировки и правильность характеристик по документам нельзя
назначать автоматически. Автономное решение CAPTCHA не входит в критерии сдачи.
