# Автоматическая актуализация ссылок до поиска — 25.09.2026

## Решение владельца

Приоритет полного MacBook-цикла: сначала актуализировать ссылки объявлений по
`unique_id`, затем искать объявления по фильтрам. Браузерные посещения проводить
в режиме инкогнито. Таблицу маркетинга и объявления на площадках не изменять.

## Контракт выполнения

1. Импортируется таблица маркетинга и сохраняется её снимок.
2. В приватных временных контекстах видимого Chrome просматриваются каталоги
   дилера и прямые карточки. Контекст закрывается после каждого посещения;
   cookies, local storage и история не переносятся в следующее посещение.
3. Фид сравнивается с активными карточками дилера. Автозамена разрешена только
   для одного ASCII `unique_id` с точным совпадением в фиде и описании карточки,
   одной строки фида и однозначной связи её VIN с записью Monitoring. Дополнительно
   проверяются принадлежность новому каталогу, валидность URL, статус карточки,
   свежесть сверки, целостность снимка и отсутствие URL у другой машины.
4. Новая ссылка записывается в Monitoring через штатный журнал смены ссылок.
   Старый URL, источник, ID, цикл, проверка и строка фида остаются в истории.
   Новая сверка относится к новому URL, а старая не переписывается.
5. После этого фиксируется неизменяемый roster для поискового этапа. Поиск и
   проверка прямых карточек запускаются только при полной сверке ID и отсутствии
   заблокированных замен. Иначе цикл становится `partial`, `search_skipped=true`;
   старые ссылки не выдаются за проверенные текущие объявления.

Совпадение модели, цены, фото, одного `AvitoId`, несколько кандидатов и
кириллический двойник ID **не разрешают автоматическую запись**. Такие случаи
остаются в очереди разбора; при незавершённой сверке поиск не запускается.
Отметка «продано» на старой карточке не является фактом продажи машины.

## Проверка и ограничения

- Unit/интеграционные тесты проверяют порядок этапов, приватный контекст,
  сохранение старого URL и отказ при повреждённом доказательстве. Площадки в
  этих тестах не посещаются. На 25.09.2026: `413 passed`, Ruff и
  `git diff --check` без замечаний.
- Приватный контекст уменьшает влияние ранее накопленных cookies, но **не**
  гарантирует одинаковую выдачу для всех покупателей и не обходит защиту
  площадок. CAPTCHA, вход и HTTP-блокировка остаются состоянием `blocked`.
- Новое поведение включено в полном host-runner цикле; прежний флаг
  `--placement-identity` оставлен только для совместимости.
- Подключение к запущенному Chrome по CDP и открытие временного приватного
  контекста на `about:blank` проверены локально без посещения площадок.
  Живой MacBook-прогон фиксируется отдельно от прохождения тестов.

## Первый живой цикл и обнаруженный дефект

После замены двух ранее подтверждённых Auto.ru ссылок запущен цикл
`90e27652-f7aa-4ec8-bd97-ab5a7343b1f9`. Обе новые ссылки стали текущими в
Monitoring, старые доступны в `ListingLinkEvent`; маркетинговый источник не
редактировался. Сам цикл завершился `partial`, `search_skipped=true`: Playwright
не смог подключиться к прежнему Chrome CDP на `19222` ни для Auto.ru, ни для
Avito. На локальном повторе драйвер завершился из-за service worker расширения
в старом профиле. Это техническая недоступность обхода, **не** доказанный
непоказ объявлений.

Коррекция: отдельный ранее не использованный профиль
`artifacts/local_chrome_isolated_profile`, порт `19223` и запуск Chrome с
`--disable-extensions`. Старый профиль не удалялся и не изменялся. На новом
профиле три последовательных подключения Playwright с временным приватным
контекстом к `about:blank` прошли без ошибки; это локальная CDP-проверка, а не
приёмка Auto.ru/Avito. Дополнительно исправлен terminal-код: пропущенный поиск
теперь возвращает `partial`, а не ошибку вывода из-за отсутствующих счётчиков.
