# Автоматическая актуализация ссылок до поиска — 25.09.2026

## Решение владельца

Приоритет полного MacBook-цикла: сначала актуализировать ссылки объявлений по
`unique_id`, затем искать объявления по фильтрам. Браузерные посещения проводить
в режиме инкогнито. Таблицу маркетинга и объявления на площадках не изменять.

## Контракт выполнения

1. Импортируется таблица маркетинга и сохраняется её снимок.
2. В приватных временных контекстах видимого Chrome просматриваются каталоги
   дилера и прямые карточки. Контекст закрывается после каждого посещения;
   cookies, local storage и история не переносятся в следующее посещение.
3. Фид сравнивается с активными карточками дилера. Автозамена разрешена только
   для одного ASCII `unique_id` с точным совпадением в фиде и описании карточки,
   одной строки фида и однозначной связи её VIN с записью Monitoring. Дополнительно
   проверяются принадлежность новому каталогу, валидность URL, статус карточки,
   свежесть сверки, целостность снимка и отсутствие URL у другой машины.
4. Новая ссылка записывается в Monitoring через штатный журнал смены ссылок.
   Старый URL, источник, ID, цикл, проверка и строка фида остаются в истории.
   Новая сверка относится к новому URL, а старая не переписывается.
5. После этого фиксируется неизменяемый roster для поискового этапа. При
   неполной, но доступной ID-сверке поиск запускается только для машин, чья
   текущая ссылка подтверждена каталогом. Остальные получают `review_required`,
   весь цикл — `partial`. При недоступном фиде/отчёте поиск не запускается
   (`search_skipped=true`). Старые ссылки не выдаются за проверенные текущие.

Совпадение модели, цены, фото, одного `AvitoId`, несколько кандидатов и
кириллический двойник ID **не разрешают автоматическую запись**. Такие случаи
остаются в очереди разбора и не получают вывод о позиции в поиске.
Отметка «продано» на старой карточке не является фактом продажи машины.

## Проверка и ограничения

- Unit/интеграционные тесты проверяют порядок этапов, приватный контекст,
  сохранение старого URL и отказ при повреждённом доказательстве. Площадки в
  этих тестах не посещаются. На 25.09.2026: `418 passed`, Ruff и
  `git diff --check` без замечаний.
- Приватный контекст уменьшает влияние ранее накопленных cookies, но **не**
  гарантирует одинаковую выдачу для всех покупателей и не обходит защиту
  площадок. CAPTCHA, вход и HTTP-блокировка остаются состоянием `blocked`.
- Новое поведение включено в полном host-runner цикле; прежний флаг
  `--placement-identity` оставлен только для совместимости.
- Подключение к запущенному Chrome по CDP и открытие временного приватного
  контекста на `about:blank` проверены локально без посещения площадок.
  Живой MacBook-прогон фиксируется отдельно от прохождения тестов.

## Первый живой цикл и обнаруженный дефект

После замены двух ранее подтверждённых Auto.ru ссылок запущен цикл
`90e27652-f7aa-4ec8-bd97-ab5a7343b1f9`. Обе новые ссылки стали текущими в
Monitoring, старые доступны в `ListingLinkEvent`; маркетинговый источник не
редактировался. Сам цикл завершился `partial`, `search_skipped=true`: Playwright
не смог подключиться к прежнему Chrome CDP на `19222` ни для Auto.ru, ни для
Avito. На локальном повторе драйвер завершился из-за service worker расширения
в старом профиле. Это техническая недоступность обхода, **не** доказанный
непоказ объявлений.

Коррекция: отдельный ранее не использованный профиль
`artifacts/local_chrome_isolated_profile`, порт `19223` и запуск Chrome с
`--disable-extensions`. Старый профиль не удалялся и не изменялся. На новом
профиле три последовательных подключения Playwright с временным приватным
контекстом к `about:blank` прошли без ошибки; это локальная CDP-проверка, а не
приёмка Auto.ru/Avito. Дополнительно исправлен terminal-код: пропущенный поиск
теперь возвращает `partial`, а не ошибку вывода из-за отсутствующих счётчиков.

## Второй живой цикл: неполная ID-сверка, 25.09.2026

Цикл `a59ac534-0c25-4488-8ed1-3a49a2566b1f` прошёл оба каталога дилера
через новый приватный Chrome: Auto.ru дал 25+4 карточки, Avito — 28. Ошибки
CDP больше не было. ID-отчёт получил 82 находки, в том числе 12 карточек без
ID, 53 ID не подтверждены в проверенной выборке, 2 строки с неоднозначным VIN
и 2 машины без текущей ссылки. Лимит 40 прямых ID-проверок меньше 57 найденных
карточек. Старое правило требовало *полной* ID-сверки и поэтому остановило
весь поиск (`partial`, `search_skipped=true`), хотя часть текущих ссылок уже
была подтверждена. Автозамен в этом цикле не было.

Коррекция: лимит повышен до 80; после любой доступной ID-сверки поиск идёт по
подтверждённым ссылкам, а неопределённые исключаются на уровне конкретной
машины. Проверенный снимок прямой карточки, уже полученный при ID-сверке,
повторно используется на этапе прямых карточек без второго обращения к сайту.
Нужен следующий живой цикл для проверки этого поведения и результата поиска.

## Третий живой цикл: поиск после актуализации, 25.09.2026

Цикл `e245a78b-4f26-43d9-adc1-61fe21253e75` подтвердил новый порядок:
ID-сверка завершилась до первого поискового фильтра, затем Auto.ru проверил
9 фильтров и 15 страниц без технических ошибок поиска. В результатах Auto.ru:
7 `found`, 14 `absent_confirmed`, 2 `absent_uncertain`, 5 `review_required`.
Это наблюдения по конкретным фильтрам и моменту цикла, не статус продажи.

Обе ранее заменённые V-Class ссылки в последней сверке имеют `verified`, а
новые карточки — `active`. В первых трёх страницах фильтра «Mercedes-Benz
V-Class — новые» обе не встретились: по каждой записано `absent_uncertain`,
сохранён ожидаемый **новый** URL и три страницы со статусом `results`. Это
означает «дальше третьей страницы или не показано в этом окне», а не
«объявление снято».

Avito в этом цикле вернул HTTP 429 на первой странице каталога. Повторных
обращений к нему в рамках цикла не было; все 6 фильтров Avito остались без
поисковых страниц и соответствующие машины получили `review_required`.
Итог цикла `partial`: 26 прямых проверок Avito пропущены после блокировки,
14 ссылок отсутствовали, 23 снимка текущих карточек Auto.ru переиспользованы
из ID-этапа. Отчёт ID-сверки неполон по Auto.ru из-за 13 карточек без
распознанного ID; это может быть и проблема данных, и проблема чтения описания,
поэтому не приписывается маркетингу без отдельной проверки снимков.

Новая автоматическая замена в этом цикле не потребовалась (`updated=0`): две
точные ссылки были актуализированы ранее. Отдельная приёмка автозаписи на
следующей реальной перевыкладке остаётся открытой; unit-тест проверяет её
логически, но не заменяет живое наблюдение.
