# Автоматическая сводка для маркетинга

После каждого штатного цикла программа формирует раздел «Что проверить
маркетингу» и файлы `cycles/<cycle_id>/analytical_summary.json` и
`cycles/<cycle_id>/marketing_summary.txt` внутри `EVIDENCE_DIR`.
Текст доступен из дашборда и защищённого
`GET /api/v1/status/cycles/<cycle_id>/marketing-summary` для ролей
admin/operator/marketing/sales_director. Ничего автоматически не отправляется.

Сводка не требует чата, LLM, API-ключа или нового посещения площадок. Она
применяет проверяемые правила к уже собранным фактам. Это не неограниченная
семантическая экспертиза произвольного описания: новые виды ошибок требуют
добавления правил либо отдельного разбора. Правильное значение характеристик
по документам подтверждает человек.

## Как читать

- В прогоне одной площадки вопросы размещения и ссылок другой площадки не
  формируются. Для неё выводится «Площадка не проверялась»; это не ошибка
  размещения и не доказательство отсутствия автомобиля.
- «Публикация снова активна» требует доказанного предыдущего отсутствия или
  прочитанного снятого объявления. После заблокированного/неполного посещения
  используется «Активность публикации подтверждена», без заявления о восстановлении.
  Старые сигналы восстановления без такого основания уточняются при чтении
  отчёта в памяти; оригинальные файлы и контрольные суммы не изменяются.

- Сначала годы, цены и НДС; ниже размещение и unique_id; отдельно менее срочные
  вопросы качества исходных данных. У каждого вопроса есть автомобиль,
  публикации, основание, источники и конкретное действие.
- Замечания по одному unique_id и полю объединяются между площадками. Карточка
  без ID не связывается с другой по цене, модели или VIN объявления.
- Повторное замечание определяется по предыдущему сохранённому циклу, указанному
  в baseline сигналов. При отсутствии сравнимого baseline надпись «новое» не
  используется. Исчезнувшее расхождение не переносится в новый список автоматически.
- Отсутствие публикации учитывается только при полном каталоге и наличии
  ожидания в основной таблице. Непрочитанная карточка даёт ограничение. У строки
  без установленного unique_id отсутствие старой ссылки — вопрос связи/ссылки,
  а не доказанное отсутствие автомобиля. Перевыкладка без ID не исключена.
- Известное партнёрское размещение показывается отдельно; само отсутствие
  объявления А1 и исходный статус цикла остаются сохранены. Активность у партнёра
  этим исключением не подтверждается. Если объявление вновь появляется у А1,
  его активность показывается как наблюдаемый факт.
- Счётчик вопросов не равен числу автомобилей: одна машина может иметь
  несколько разных замечаний. Фактическое число неактивных публикаций на
  дашборде может включать известное исключение; это не число требований восстановить.

## Подтверждения и исключения

Локальный реестр: `<EVIDENCE_DIR>/monitoring_decisions.json`. Он хранится рядом
с доказательствами, не в Git и не в исходной таблице. Запись включает точный
unique_id, вид решения, площадку, автора подтверждения, основание и дату записи.
Три вида: `confirmed_year`, `placement_exception` и `open_question`.

Подтверждённый год напрямую сравнивается с годами в карточке, описании,
основной строке таблицы и фиде. Даже если эти источники согласованно указывают
неверный год, сводка создаёт замечание относительно подтверждения. Отсутствие
года остаётся ограничением, а не совпадением. Открытый вопрос сохраняет историческое основание и не
выдаётся за новое подтверждённое расхождение. Исключение для партнёра действует
только на выбранной площадке и exact unique_id; оно не подавляет цену, НДС,
идентификацию или другие ошибки этой машины.

Если один unique_id связывает разные автомобили внутри таблицы, автоматическая
привязка и замена ссылок блокируются. Сводка показывает конфликт вместо выбора
первой строки. VIN используется только для проверки связей внутри таблицы.
Ссылка на другой сайт или на раздел площадки отмечается как ошибка ссылки;
она не доказывает, что публикация неактивна.

Реестр читается и валидируется перед построением нового цикла. Неизвестный
формат, противоречащие решения, неверный ID, отсутствие основания, symlink или
нечитаемый файл приводят к явному предупреждению без применения исключений.
Можно задать `valid_until`; просроченная запись не применяется. Отзыв сохраняется
в том же журнале (`active=false`, основание и время отзыва).

Операторские команды (из корня проекта, значения в угловых скобках заменить):

```sh
PYTHONPATH=src:. .venv312/bin/python scripts/monitoring_decisions.py \
  --evidence-dir artifacts/evidence list

PYTHONPATH=src:. .venv312/bin/python scripts/monitoring_decisions.py \
  --evidence-dir artifacts/evidence year --unique-id '<unique_id>' --value 2026 \
  --confirmed-by '<кто подтвердил>' --basis '<основание и источник>'

PYTHONPATH=src:. .venv312/bin/python scripts/monitoring_decisions.py \
  --evidence-dir artifacts/evidence partner --unique-id '<unique_id>' --source avito \
  --partner '<партнёр>' --confirmed-by '<кто подтвердил>' --basis '<основание>'

PYTHONPATH=src:. .venv312/bin/python scripts/monitoring_decisions.py \
  --evidence-dir artifacts/evidence question --unique-id '<unique_id>' \
  --question '<что требуется уточнить>' --confirmed-by '<кто открыл вопрос>' \
  --basis '<дата и содержание прежнего разбора; что ещё не перепроверено>'

PYTHONPATH=src:. .venv312/bin/python scripts/monitoring_decisions.py \
  --evidence-dir artifacts/evidence revoke --id '<id решения из list>' \
  --basis '<почему отозвано>'
```

Изменение и отзыв решения влияют на следующие циклы. Новые циклы сохраняют
снимок действовавших решений вместе со сводкой; позднее изменение реестра не
переписывает их историю. Для старых циклов без такой сводки раздел строится
при чтении отчёта по нынешнему реестру с отдельными датами наблюдения и анализа.
Оригинальный файл цикла и его partial/completed не меняются.

## Проверка на архиве

```sh
PYTHONPATH=src:. .venv312/bin/python scripts/build_marketing_summary.py \
  --report artifacts/evidence/cycles/<cycle_id>/placement_reconciliation.json \
  --evidence-dir artifacts/evidence \
  --search artifacts/evidence/cycles/<cycle_id>/search_collection.json \
  --output-dir artifacts/evidence/cycles/<cycle_id>/post_run_review/automatic_brief
```

Команда сначала проверяет целостность сохранённого отчёта/доказательств, сохраняет
SHA256 исходного отчёта и не меняет его. Если доказательства не проходят проверку,
сводка не создаётся как подтверждённая. Каталог результата должен быть новым:
существующие сводки не перезаписываются. Это не создаёт цикл и не обращается
к площадкам, Google Sheets, Bitrix или модели.

Файлы публикуются комплектом с контрольными суммами: для штатного цикла
`report_bundle.ready.json`, для отдельного пересчёта `analytical_summary.ready.json`.
Отчёт нового формата принимается только после проверки всего комплекта.
При обычной ошибке записи новые файлы откатываются, чужие файлы сохраняются.
После прерывания идентичный комплект можно допубликовать по pending-манифесту;
изменённые результаты поверх существующих не записываются.

Полная автоматическая сверка двигателя, мощности, коробки и привода остаётся
отдельной доработкой. Наличие сводки не означает, что все характеристики каждого
объявления прочитаны или подтверждены.

## Несколько блоков на листе фида

CSV-парсер читает каждый повторный заголовок отдельно. Строки пояснений и пустые
разделители не являются автомобилями; исходные номера строк и столбцов сохранены.
Совместимые повторы одного exact unique_id внутри одного листа объединяются
только при подтверждённой внутренней связи: одинаковом VIN либо одинаковом
непустом AvitoId, без противоречий VIN, AvitoId и действия публикации Auto.ru.
Повторы между листами new/used и противоречивые записи остаются неоднозначными.

Для каждого поля сохраняются ссылки на реальные исходные ячейки. Одинаковые
значения и заполнение пропусков не требуют выбора первого/последнего блока.
Разные непустые значения не выбираются: поле остаётся неизвестным, варианты
сохраняются, существенные расхождения показываются отдельно. Варианты описаний
могут подтвердить ID только если каждый независимо содержит тот же exact ID.
Установить фактически подключённый к площадке блок по этому сравнению нельзя.
Структура фида и повторы остаются вопросом для маркетинга и подрядчика.

Повторный разбор сохранённых CSV и карточек:

```sh
PYTHONPATH=src:. .venv312/bin/python scripts/review_feed_blocks.py \
  --cycle-id '<cycle_id>' --evidence-dir artifacts/evidence \
  --csv-dir '<каталог сохранённых CSV и capture_metadata.json>' \
  --output-stem '<новое имя результата>'
```

Команда проверяет контрольные суммы CSV и доказательства карточек, использует
только локальный MockTransport и пишет отдельный комплект в `content_review/`.
Новых циклов, запросов к площадкам и изменений базы она не создаёт. Для показа
результата в существующем дашборде применяется обычная привязка content_review
с SHA256 к исходному отчёту; исторический статус цикла сохраняется.

## Незаполненный VIN и прежние подтверждения владельца

После независимого подтверждения unique_id публикации строка с пустым VIN может
быть связана по единственной объявленной в книге ссылке Auto.ru либо по AvitoId
строки фида того же ID и ссылке X основного листа. Сначала проверяется ID, затем
связь строк. Это не позволяет получать ID публикации из URL, цены или VIN
объявления. Противоречивые VIN/ID и несколько подходящих строк блокируют привязку.
При этом учитываются и конкурирующие актуальные строки с заполненным VIN:
пустое поле одной строки не делает её приоритетной. Если конфликт обнаружен
позже в том же проходе, ранее выполненные сравнения по спорной связи отменяются,
а карточки на дашборде не объединяются с произвольно выбранной строкой.

Для карточки без опубликованного ID можно показать ожидаемый ID строки книги
как вопрос маркетингу; публикации он не присваивается. Сохранённое подтверждение
владельца может применяться отдельно, после проверки актуального локального
реестра, URL и параметров подтверждённой карточки. В повторном разборе
`review_saved_cycle(..., db=...)` выполняет только чтение этого реестра; обычная
офлайн-команда без `db` не назначает такие подтверждения самостоятельно.
Даже при сохранённом подтверждении отсутствие ID в описании остаётся отдельным
замечанием для маркетинга и подрядчика.
