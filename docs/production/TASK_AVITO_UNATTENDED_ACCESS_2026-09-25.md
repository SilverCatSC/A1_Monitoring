# Avito без присутствия оператора: задача доступа, не «решатель CAPTCHA»

Статус: **заблокировано внешним доступом; инструмент не реализован и не принят**.
Владелец требует, чтобы проверка Avito могла выполняться, когда он не находится
за компьютером. Нельзя объявлять это решённым наличием OCR, AI-модели,
повторных запросов или кнопки «Продолжить»: текущий отказ начинается с HTTP 429
и сообщения площадки «Доступ ограничен: проблема с IP».

## Task → Test → Analyse

- Последний контролируемый цикл `e59ef095-5a6a-4d5c-8d83-9b434d63e4cd`
  оставил 46 проверок Avito в `pending`. Первый запрос к каталогу дилера дал
  HTTP 429. Это не доказательство отсутствия объявлений.
- Попытка открыть тот же URL через доступный инструмент управления браузером
  была остановлена ограничением инструмента. Продолжать её другим способом
  ради обхода этого ограничения нельзя; поведение страницы после кнопки
  «Продолжить» не наблюдалось.
- 25.09.2026 запрос заголовков официальной страницы каталога API
  `https://developers.avito.ru/api-catalog/autoload/documentation` получил
  перенаправление на `www.avito.ru/developers/...`, затем HTTP 429. Поэтому
  актуальные методы и объём разрешённого доступа не подтверждены.
- В текущей конфигурации Monitoring нет настроенного Avito API-клиента.
  Таблица/фид отражают ожидаемое размещение, но сами по себе не доказывают
  фактический статус публичной карточки и место в выдаче.

Вывод: гарантированный автономный «решатель» именно этой блокировки нельзя
построить и принять по имеющимся данным. Интерактивная задача после кнопки
может требовать человека, а результат в одном временном приватном контексте
не доказан для следующих посещений. Смена IP, прокси, сторонние CAPTCHA-сервисы,
чужие cookies и серия повторов не являются принятым production-путём.

## Целевая архитектура

1. **Собственные объявления** — изучить и, если компания имеет право и
   доступ, подключить официальный read-only интерфейс аккаунта/автозагрузки
   Avito. Контракт ответа для Monitoring: `unique_id` из фида, ID и URL
   публикации на Avito, статус/причина ошибки, время источника. Сначала
   подтвердить актуальные методы и реальные поля на одном тестовом ID;
   никакие названия методов пока не зафиксированы как факт. Официальная
   [страница Avito для бизнеса](https://avito.akamaized.net/business/tools/messenger)
   подтверждает существование API-ключей в разделе «Для профессионалов»,
   но относится к мессенджеру и **не доказывает** доступность нужных методов
   мониторинга объявлений в данном аккаунте.
2. **Публичная позиция в поиске** — отдельная проверка, потому что доступ к
   собственным объявлениям логически не равен наблюдению выдачи обычного
   покупателя. Если разрешённого источника выдачи нет, показывать
   `позиция не проверена`, а не «дальше третьей страницы».
3. **Управление неполнотой** — сохранять причину и evidence по каждому
   `pending`, продолжать независимые источники, не создавать бизнес-выводы
   из HTTP 429. Реализовать адресное возобновление ожидающих заданий после
   появления разрешённого доступа; прежний цикл и его доказательства
   остаются неизменяемыми. Не делать фоновую серию запросов к заблокированной
   странице.

## Что требуется от владельца аккаунта Avito

- Назначить ответственного за разрешённый доступ к данным дилерского
  аккаунта и подтвердить, допускается ли read-only API/интеграция для этой
  задачи. Не нужен личный пароль в чате.
- Предоставить актуальную документацию/права приложения, ID аккаунта и
  ограниченные ключи через локальное хранилище секретов, а не Git или переписку.
- Подтвердить, какой именно фид публикует автомобили, и дать контрольный
  пример `unique_id → ID объявления Avito → текущий URL → статус`.
- Согласовать ожидаемый результат по публичной позиции: нужен ли он при
  недоступной выдаче, и есть ли разрешённый источник для его получения.

## Gate реализации

Нельзя начинать интеграцию по догадке о методах API. После получения
документации и прав: (a) зафиксировать формат и лимиты; (b) написать адаптер
и тесты с локальными фикстурами; (c) провести один read-only live-test на
контрольном ID; (d) проверить перевыкладку, неполные ответы и отсутствие
ложного «снято»; (e) лишь затем включить в рабочий цикл. До этого M7 остаётся
`partial`, а пользователь видит точный объём неисполненных проверок.
