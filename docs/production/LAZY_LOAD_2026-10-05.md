# Lazy load в локальном обходе

Цель — уменьшить лишние переходы и нагрузку при проверке объявлений. Влияние
на частоту CAPTCHA живым запуском пока не подтверждено.

## Поведение

- Auto.ru и Avito используют штатную видимую кнопку «Показать ещё»/«Загрузить ещё»
  в основном блоке выдачи или непосредственно после него, если такая кнопка есть.
- Кнопки рекомендаций, рекламы, похожих автомобилей и ссылки на другую страницу
  не используются для lazy load. Неизвестные селекторы и скрытые API не угадываются.
- Следующая подгрузка начинается только после предыдущей и с паузой текущего
  профиля. Автоматических перезагрузок нет.
- Если все ожидаемые объявления найдены и имеют снимки карточек, поиск заканчивается
  раньше. Это подтверждение целевых объявлений, а не полного исчерпания каталога.
- Новые карточки объединяются по ID. Уже найденные целевые карточки получают снимки
  до следующей подгрузки, чтобы виртуализация списка не уничтожила доказательства.
- Неизменившаяся выдача, смена поискового диапазона или исчерпание лимита без полного
  покрытия дают неполную проверку. Отсутствие объявления этим не подтверждается.
- CAPTCHA во время подгрузки обрабатывается тем же ручным ожиданием в текущей вкладке.
  Если проверка не снята, сканирование помечается как блокировка источника
  (`page_N_state=blocked`, `page_N_block_reason`), и оставшиеся фильтры этого
  источника не идут в заблокированную площадку — как при блокировке основной
  страницы. Обычные ошибки парсера, смены диапазона, снимков и таймауты остаются
  техническими ошибками, а не блокировкой.

## Приоритет пагинации и счётчики (обновление 2026-10-06)

Штатный переход на следующую страницу — доказуемое продолжение каталога.
Пока на странице виден работающий пагинатор, оставшиеся «переходы» общего
потолка `--pages` резервируются за пагинацией: кнопки «Показать ещё»
используются только на страницах без пагинатора или когда документов в
потолке больше не осталось. Так подгрузки не «съедают» слоты задокументированных
страниц 2+. Диагностика фиксирует резерв: `page_N_lazy_budget_reserved`.
Исчерпание потолка без пагинатора и без полного покрытия по-прежнему даёт
неполную проверку (`load_budget_exhausted`), а не доказательство отсутствия.
Для строгой сверки каталога продавца полнота по-прежнему требует
`exhausted`: пройденный бюджет без доказанного конца каталога не деактивирует
кандидатов.

Счётчик «Показать N предложений» читается из основного блока выдачи
(`ListingCars__items`/`CardGroupOffersList__items`); скрытые блоки
(`hidden`, `display:none`, `aria-hidden`) удаляются до подсчёта. Если
кандидатные счётчики расходятся, значение не принимается (None).
Маркеры пустой выдачи требуют текста или DOM-компонента в основном блоке:
скрипты, явно скрытые узлы, избранное и рекомендации исключаются. Видимый
отказ доступа в боковом блоке по-прежнему блокирует проверку. Видимость через
внешний CSS по одному HTML не определяется; неизвестная разметка остаётся
`unrecognized`. Отсутствие документа, ошибки доказательств и HTTP 5xx при
подгрузке относятся к техническим ошибкам, а не к CAPTCHA.

## Лимиты и наблюдение

`CATALOGUE_LAZY_LOAD_ENABLED=true` включает режим. Его можно отключить через
`false`. По умолчанию разрешено не более 3 подгрузок на страницу
(`CATALOGUE_LAZY_LOAD_MAX_BATCHES`), ожидание изменений ограничено 6 секундами
(`CATALOGUE_LAZY_LOAD_TIMEOUT_SECONDS`).

Переходы страниц и нажатия подгрузки вместе ограничены параметром `--pages`.
Например, при `--pages 3` допустимы одна начальная страница и две подгрузки;
четвёртого действия не будет. Число сетевых запросов, которые сайт выполняет
внутри одного действия, этим не задаётся.

Журнал и dashboard показывают события `lazy_load_started`/`lazy_load_finished`.
Диагностика фильтра сохраняет `load_actions`, `page_N_lazy_batches`,
`page_N_lazy_outcome`, `target_coverage_complete` или `load_budget_exhausted`.

Локальные браузерные тесты проверяют подгрузку через XHR без новой навигации,
виртуализацию карточек, раннее завершение по целям и ограничение нагрузки.
На площадке без подходящей кнопки остаётся обычный обход страниц.
