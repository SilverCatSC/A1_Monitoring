# A1 Monitoring: основной запуск на Mac

По текущему решению владельца этот MacBook — основной production host. Проверено
на MacBook Pro, Apple M2 Pro, 12 ядер, 16 ГБ общей памяти, macOS 26.6.2.
Текущая staged-версия приложения — 0.14.0. Это решение о host не закрывает M7:
живой controlled cycle, VPSUS split-tunnel, роли и будущий LaunchAgent требуют
отдельных evidence. Windows/MSI остаётся резервным, непринятым handoff.

## Установка с нуля

Краткий каталог всех команд: [установочные скрипты macOS](INSTALL_SCRIPTS_MACOS.md).

Нужны Python 3.12, Google Chrome, Docker с работающим Compose и интернет для
первичного скачивания пакетов. На текущем Mac всё это уже установлено.

Полная целевая установка включает мониторинг, локальный llama.cpp, Hermes,
Q00/Ouroboros, модель Qwen3.5-9B Q4 и vision-проектор. Требуется около 8 ГБ
свободного места:

```bash
cd /Users/filaret/Desktop/Monitoring
./scripts/install_all_macos.sh
```

Скрипт ставит недостающие Homebrew, Python 3.12, Git, Chrome, Docker Desktop,
зависимости проекта, uv, llama.cpp, hf, изолированный Hermes и Ouroboros.
Он загружает модель около 5,3 ГБ и vision-проектор около 0,9 ГБ. Существующие
компоненты не обновляются целиком.
Если модель пока загружать нельзя: `./scripts/install_all_macos.sh --skip-model`.

На уже настроенном Mac достаточно запуска приложения:

```bash
cd /Users/filaret/Desktop/Monitoring
./scripts/start_local.sh
```

Адрес: [локальный дашборд](http://127.0.0.1:18000/api/v1/dashboard).
Файл «Открыть дашборд.command» в корне проекта предназначен для запуска через
Finder после проверки его executable-bit.
Существующая `.env` сохраняется. Не меняйте пароль уже созданной базы и
не удаляйте Docker volumes. Программа доступна только на этом Mac через loopback.

Перед первым запуском двойным кликом убедитесь, что оба Finder-launcher файла
исполняемы: `test -x './Открыть дашборд.command' && test -x './Запустить мониторинг.command'`.
Если проверка не проходит, используйте команду из Terminal выше и не считайте
Finder-путь принятым до восстановления executable-bit в контролируемом checkout.

## Реальная проверка с VPSUS split-tunnel

После запуска приложения не отключайте VPSUS и не закрывайте ChatGPT/Codex ради
мониторинга. Подтвердите в обычном Chrome согласованный split-tunnel: ChatGPT
доступен по утверждённому VPN/direct-маршруту, Auto.ru и Avito — по direct browser
rules Monitoring. Не меняйте VPN, reconnect или bypass-правила без отдельного
подтверждения владельца. Оставьте Docker и пользовательскую сессию запущенными.

Следующая команда является ручным controlled cycle, а не доказательством нового
live run этой документацией. Выполняйте её только после соответствующего M7 gate.

В Терминале:

```bash
cd /Users/filaret/Desktop/Monitoring
./Запустить\ мониторинг.command
```

Или дважды нажмите «Запустить мониторинг.command» в Finder.
Запускатель выполняет обе площадки, первые три страницы, осторожный темп,
открывает дашборд, сохраняет лог и удерживает Mac от автоматического сна.
Закрытие крышки или завершение пользовательской сессии может прервать работу.
С учётом прямых карточек, последовательного Hermes и Ouroboros ориентируйтесь на
45–90 минут; это диапазон планирования, а не гарантия площадок или модели.

Последовательность: импорт реестра → каталоги продавца и сверка ссылок →
поисковые фильтры → последовательное открытие прямых карточек → сохранение результата.
В терминале эта стадия видна как `КАРТОЧКА N/всего`; она намеренно увеличивает время
прогона, зато отличает непоказ в выдаче от проданного, снятого или закрытого URL.
Chrome видимый, с отдельным локальным
профилем `artifacts/local_chrome_profile`. Не закрывайте управляемые вкладки.
Ход проверки виден в Chrome, терминале и блоке прогресса дашборда.

Результаты:

- Лог запуска: `artifacts/manual_scan_YYYYMMDD_HHMMSS.log`.
- Снимки карточек и доказательства: `artifacts/evidence/`.
- История страниц, машин и ссылок: PostgreSQL; просмотр через дашборд.
- Неоднозначные перевыкладки: раздел «Сверка ссылок».

`LOCAL_SCAN_PARTIAL` означает технические проблемы или неподтверждённые ссылки,
а не отсутствие всех машин. CAPTCHA/403/429/таймаут нельзя засчитывать как непоказ.
Паузы не гарантируют отсутствие CAPTCHA. Остановите цикл через `Ctrl+C`, если
требуется ручной разбор; не запускайте второй цикл поверх первого.

## График через LaunchAgent — static-only, пока не принят

Основной MacBook использует только per-user GUI LaunchAgent, а не container
scheduler или LaunchDaemon. Поставленные static-only скрипты
`scripts/run_monitoring_host_macos.sh` и
`scripts/register_monitoring_launchagent_macos.sh` предназначены для ровно одного
cautious цикла с видимым Chrome в активной пользовательской сессии.

Регистратор по умолчанию показывает план; только явный `--apply` может создать
`com.silvercatsc.a1monitoring.interactive-cycle`. Он не запускает scan при
регистрации. `RunAtLoad=false` и `KeepAlive=false`; `--watch` остаётся ручным
foreground-loop. Не включайте `SCHEDULER_ENABLED=true` как замену этому контуру.
Ни runner, ни LaunchAgent не заявлены живо проверенными: пока есть только
static-only contract. Отдельный M7 record должен зафиксировать GUI-trigger, один
`cycle_id`, отсутствие параллельного worker, корректную обработку `partial` и
TCC/Desktop access для проекта, Terminal, Chrome и launchd. Не выдавайте
permissions автоматически и не используйте locked screen как способ запуска. См.
[MacBook primary-host decision](production/MACBOOK_PRIMARY_HOST_2026-09-14.md).

Для приёмки вручную сверьте несколько автомобилей: Москва/0 км на обеих площадках,
общий список новых Auto.ru, правильный ID объявления, цена, номер страницы 1–3,
снимок именно этой машины, прямой URL и его состояние. Для Avito проверьте наличие
НДС в описании. Рекомендации и другие города не должны учитываться.

## Hermes и Ouroboros на Mac

**Целевая система включает оба агента.** Hermes и Q00/Ouroboros установлены в
изолированные каталоги проекта. Инференс обслуживает `llama.cpp` на loopback;
облачные LLM и резервный cloud fallback не настроены.

Рекомендуемый первый пилот — Hermes с локальным `llama.cpp`/Metal на Apple Silicon.
Документация Hermes подтверждает локальные модели и собственный либо внешний
сервер: [Local Models](https://hermes-agent.nousresearch.com/docs/user-guide/local-models/).
Никаких облачных LLM, ключей облачных моделей или резервного переключения на облако.
Локальный HTTP-интерфейс модели на `127.0.0.1` не является внешним LLM API.

16 ГБ — общая память macOS, Chrome, Docker и модели. Поэтому сервер ограничен
четырьмя вычислительными потоками, одним одновременным запросом, batch 256,
ubatch 128, ответом до 768 токенов и паузой 8 секунд между малыми заданиями.
Контекст 65 536 сохранён из-за минимального требования Hermes, но весь реестр в
него больше не загружается одним запросом. Модель выгружается после QA, если не
была запущена заранее. [Настройка моделей Hermes](https://hermes-agent.nousresearch.com/docs/integrations/providers/).

В проекте под Ouroboros понимается **Q00/ouroboros**, а не одноимённые проекты
других авторов. В его проектном профиле и runtime, и внутренние LLM-вызовы явно
переключены на Hermes. Телеметрия выключена, параллельность ограничена одним
worker, проверка разными облачными моделями отключена, изменения выполняются в
отдельных git-worktree. [Официальный адаптер Hermes](https://github.com/Q00/ouroboros/blob/main/docs/runtime-guides/hermes.md).

После установки полный запуск работает так: мониторинг площадок завершается,
система читает головную таблицу и детерминированно сопоставляет VIN, цену,
марку/модель, комплектацию, год и ссылки с реестром и найденными карточками.
Затем поднимается локальная модель: Hermes последовательно проверяет данные одного
автомобиля, распознаёт один сохранённый снимок и только после этого ранжирует
готовые замечания. Ouroboros проверяет полноту, происхождение доказательств и
противоречия в компактном результате, не повторяя первичную работу Hermes.
Результаты сохраняются в `artifacts/head_table_audits/`,
`artifacts/agent_work_units/`, `artifacts/agent_reviews/` и
`artifacts/ouroboros_reviews/`; модель выгружается из памяти, если не была запущена
заранее. Сбой AI помечает общий запуск как частичный, но не переписывает наблюдения
площадок.

Ouroboros использует отдельные `artifacts/ouroboros_home`,
`artifacts/hermes_maintenance_home` и `artifacts/ouroboros_worktrees`. Во время
каждой проверки он выступает read-only аудитором пакета доказательств. Его роль
в инженерной доработке остаётся отдельной: он не меняет код или данные во время
активного скана.

Порядок внедрения:

1. Одна локальная модель, один worker, четыре потока и последовательные задания.
2. Hermes читает результаты и снимки как данные, выдаёт замечания с
   доказательствами; не исправляет историю и не превращает ошибку доступа в непоказ.
3. Сравнить выводы с размеченными человеком примерами, измерить ложные замечания,
   время и пиковую память. Отказ модели не должен останавливать основной мониторинг.
4. Ouroboros участвует в каждом полном цикле как read-only аудитор компактного
   staged-отчёта. Для
   воспроизведения дефекта и патчей он получает отдельную задачу и отдельную копию,
   с регрессионными тестами и отчётом. Не менять работающий код в середине скана.

Подробные границы и команды: [AI-агенты](AI_AGENTS.md). AI можно проверить на
сохранённом прогоне, вообще не посещая площадки при включённом VPN.
