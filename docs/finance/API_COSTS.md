## Допущения одного полного цикла

| Работа | Количество | Вход на задание | Выход на задание |

Это 122 логических вызова до повторов. Добавлен запас **25% токенов** на
повторы/служебный контекст. Он не гарантирует покрытия произвольно длинного
reasoning или инструментального агентского цикла. Выходные бюджеты должны
включать оплачиваемые reasoning-токены, если провайдер их тарифицирует.

Расчёт:

```text
Input  = ceil((40×2000 + 80×(1000+2000) + 20000) × 1.25) = 425000
Output = ceil((40×400  + 80×250          + 2000)  × 1.25) = 47500
Cost_cycle = (Input×Price_in + Output×Price_out) / 1000000
Cost_month = Cost_cycle × запусков_в_день × 30
```

Например, Qwen: 0,425×219,6 + 0,0475×329,4 = **108,9765 ₽ за цикл**,
или **3 269,30 ₽ за 30 циклов**. Округление выполняется только в конце суммы,
а не после каждого компонента; калькулятор использует Decimal для стоимости.

## Экономичный режим без снижения частоты поискового контроля

Можно выполнять поиск четыре раза в день, но полный AI-разбор — один раз,
в остальных трёх циклах анализировать, например, только 12 изменившихся машин
и 24 снимка. По модели Qwen это **3 269,30 + 3 340,12 = 6 609,42 ₽/месяц**,
примерно на 49% ниже четырёх полных AI-циклов.

Это проектируемый режим, сейчас такого полного change-aware планировщика нет.
Число 12 — предположение о 30% изменений, не измеренный показатель проекта.
Кэш не должен подменять свежий статус старым: сохранять возраст каждого поля,
проверять TTL и делать контрольную выборку неизменившихся карточек.

## Разовые и сопутствующие затраты

API-вызовы — лишь часть бюджета. Минимальная интеграция: provider adapter для
текста/vision, безопасные ключи, timeout/retry, JSON contracts, учёт usage,
денежные лимиты и оценка на эталонах. Оценка: **24–44 инженерных часа**.

Если для внутреннего планирования условно принять **2 500 ₽/час**, получится
**60 000–110 000 ₽ разово**. Ставка приведена как допущение, а не рыночная цена.
Исправление обнаруженных P0, UI, доступ отдела продаж и миграции в эту сумму
не включены. По этому примеру первый месяц с ежедневным Qwen-анализом:
**63 269–113 269 ₽**, до внешнего хостинга/комиссий/налоговых корректировок.

Не включены: платные прокси/обход CAPTCHA (не предлагаются), hosting отчёта,
объектное хранилище, дополнительный ПК, поддержка изменений площадок,
время менеджеров, неограниченное агентское программирование.

## Сравнение с локальной моделью

| Локально | Через API |
| --- | --- |
| Нет оплаты за токены; данные остаются на ПК | Оплата по usage; часть данных передаётся провайдеру |
| Память весов, KV cache и vision занята на ПК | Эти компоненты вынесены с ПК, но Chrome/БД остаются |
| Зависимость от RAM, CPU и локальной настройки | Зависимость от сети, лимитов и доступности провайдера |
| Качество ограничено выбранной доступной моделью | Можно сравнить модели без покупки GPU |
| Обновление runtime и моделей — наша поддержка | API-контракты и тарифы также требуют поддержки |

Электричество само по себе редко делает локальную схему дорогой: при **условных**
дополнительных 40 Вт, 2 часах/день и 8 ₽/кВт·ч получится 19,20 ₽/месяц.
Это арифметический пример, не замер MSI и не тариф пользователя. Уже 2 часа
поддержки по условным 2 500 ₽/час — 5 000 ₽/месяц. Следовательно, сравнивать
нужно полную стоимость и удобство, а не только кВт·ч против токенов.

По одному факту swap нельзя рассчитать износ SSD или срок службы: нужны реальные
объёмы записей и данные накопителя. Основание для API здесь — управляемая RAM,
удобство и качество, а не недоказанный прогноз отказа диска.

## Как безопасно подключать

1. Владелец отдельно выбирает провайдера и разрешённые поля/изображения.
2. До передачи исключить внутренние комментарии, cookies, ключи; VIN передавать
   только если он действительно нужен для согласованной сверки.
3. Начать с 10–20 согласованных примеров: обычные, без VIN, снятые, перевыложенные,
   НДС в тексте, нечитаемые изображения и технические ошибки.
4. Задать лимит пилота **500 ₽** как бюджетное ограничение, не обещание фактической
   стоимости. Один полный базовый цикл Qwen занимает около 109 ₽ по расчёту.
5. Ограничить output/reasoning, число повторов и суммарный бюджет; при превышении
   оставить AI pending, а не объявлять весь мониторинг успешным.
6. Принять модель по точности/полноте/стоимости, не по красивому стилю ответа.
7. Не давать агентскому maintenance общую неограниченную квоту мониторинга.
