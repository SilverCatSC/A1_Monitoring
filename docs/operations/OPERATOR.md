# Рабочая инструкция оператора и отдела продаж

Актуальность: 14.09.2026. Программа 0.9.0. Это инструкция к существующему коду,
а не подтверждение успешного живого прогона после переноса папки.

## Что проверяем

1. Какие автомобили должны рекламироваться: активные строки маркетинга, включая
   автомобили без VIN и ещё не закупленные Maestra V800 / Mercedes VLE.
2. Какие объявления фактически есть в трёх публичных каталогах продавца.
3. На какой из первых трёх страниц заданного поиска видно каждое объявление.
4. Работает ли прямая ссылка: карточка активна, снята, продана, перенаправлена
   либо недоступна по технической причине.
5. Соответствуют ли цена, VIN, год, наличие и НДС данным маркетинга.

«В пути» — состояние поставки, а «активно» — намерение рекламировать. Одно не
заменяет другое. Отсутствующий VIN не является основанием исключить машину.

## Перед запуском

- Убедиться, что компьютер не уйдёт в сон, есть интернет и место для снимков.
- Проверить прямое открытие Auto.ru и Avito в обычном браузере. Метка
  `local_no_vpn` в команде сама по себе не отключает VPN и не меняет маршрут.
- Завершить предыдущий прогон. Не запускать параллельно ручной и плановый обход.
- Не редактировать профиль служебного Chrome и не закрывать его во время обхода.
- Открыть дашборд и отметить время предыдущего результата: старый отчёт не
  должен быть принят за новый.
- Для запуска локальной LLM закрыть тяжёлые приложения. На Mac с 16 ГБ полный
  режим пока способен снова вызвать высокое потребление памяти; не считать
  паузы между заданиями освобождением памяти модели.

## Запуск на этом Mac

В терминале:

```bash
cd /Users/filaret/Desktop/Monitoring
./scripts/start_local.sh
./scripts/local_scan.sh --engines auto_ru,avito --pages 3 --pace cautious
```

Первый сценарий собирает/поднимает приложение, БД и резервирование. Второй
обновляет реестр Monitoring, сверяет кабинеты, проверяет поиск и прямые карточки.
Он **не запускает Hermes/Ouroboros** и не выполняет отдельные аудиты головной
таблицы и сайта. Это предпочтительный первый тест самого мониторинга.

Полный сценарий, только после установки AI и оценки памяти:

```bash
cd /Users/filaret/Desktop/Monitoring
./scripts/run_full_monitoring_macos.sh
```

Он дополнительно выполняет сверку сайта, головной таблицы, Hermes и Ouroboros;
сам сохраняет общий журнал в `artifacts/manual_scan_YYYYmmdd_HHMMSS.log`.

## Запуск на Windows 11 после установки

В PowerShell, каталог без пробелов:

```powershell
Set-Location C:\work\A1_Monitoring
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\start_windows.ps1 -OpenDashboard
.\scripts\local_scan_windows.ps1 -Engines auto_ru,avito -Pages 3 -Pace cautious
```

Для полного установленного AI-контура:

```powershell
.\scripts\run_full_monitoring_windows.ps1
```

Windows-сценарий останавливает служебный Chrome и контейнеры проекта перед AI,
затем возвращает приложение. В этот промежуток дашборд может не открываться.
Живая приёмка на MSI ещё обязательна; статические тесты PowerShell её не заменяют.
Установка: [окружение](ENVIRONMENT.md).

Служебный Chrome виден на экране. В терминале отображаются стадии обхода.

| [Сверка продавца](http://127.0.0.1:18000/api/v1/dashboard/reconciliation) | Устаревшие ссылки, findings Offer и кандидаты на перевыкладку |

| [Активность](http://127.0.0.1:18000/api/v1/dashboard/activity) | События изменения данных |
| [Обратная связь](http://127.0.0.1:18000/api/v1/dashboard/feedback) | Ролевая обработка замечаний и подтверждение исправлений |
| [Состояние последнего поиска, JSON](http://127.0.0.1:18000/api/v1/status/scans/latest) | Технические итоги по площадкам |
| [Ход проверки, JSON](http://127.0.0.1:18000/api/v1/status/scans/progress) | Текущая стадия |

Эти адреса относятся к этому компьютеру, а не к общедоступному сайту.
Если порт изменён в `.env`, заменить `18000` на `APP_BIND_PORT`.

Журналы, снимки, AI-пакеты и отзывы сохраняются под `artifacts/`; наблюдения,
цены, страницы и история — в PostgreSQL. Точные каталоги указаны в
[структуре](../architecture/PROJECT_STRUCTURE.md). `latest` означает последнюю
запись конкретного этапа, **не гарантирует один и тот же цикл всех файлов**.

## Как трактовать результат

| Состояние | Что можно сказать | Что нельзя утверждать |
| --- | --- | --- |
| `found` | ID объявления найден на указанной странице в указанное время | Объявление видно всем пользователям постоянно |
| `absent_uncertain` | В проверенном объёме не найдено; подтверждения ещё недостаточно | Машина продана или реклама выключена |
| `absent_confirmed` | Повторные валидные обходы не нашли объявление в установленной глубине | Объявления нет на площадке вообще |
| `technical_error` | Надёжная проверка не состоялась | Машина отсутствует в выдаче |
| `filter_mismatch` | Требуется проверить соответствие фильтра | Объявление снято |
| Карточка «продано/снято» | Есть соответствующее подтверждение на прямой странице | У машины нет нового объявления с другим ID |

Номер страницы — статистика конкретного поиска и времени. При сравнении смотреть
также фильтр, его версию, сортировку и географию. Для обеих площадок требуется
**только Москва, радиус 0 км**; новые машины Auto.ru должны показываться общим
списком объявлений, не только группами комплектаций.

## Если появилась CAPTCHA или ошибка

1. Не перезапускать много раз подряд. CAPTCHA, 401/403/429 и тайм-аут —
   техническая недоступность, а не отсутствие машины.
2. Если служебный браузер позволяет, пройти штатную ручную проверку. Не
   использовать обход защиты, чужие cookies или автоматическое решение CAPTCHA.
3. Дождаться окончания/ошибки этапа, проверить его журнал. Если требуется
   остановка — один раз `Ctrl+C` в терминале; проверить, что процесс завершился.
4. Повторить только после восстановления доступа. Прерывание может оставить
   частичные результаты; общий набор следует проверять по времени.

## Минимальная живая приёмка

Проводит оператор без влияющего на площадки VPN. Подготовить вручную контрольные
автомобили: найденный на первой странице; найденный на второй/третьей; активная
карточка вне первых трёх; снятая/проданная; перевыложенная; без VIN; с НДС в
описании Avito. Это тестовые категории, а не утверждение, что все они есть сейчас.

Для каждого записать эталон: ссылка/ID, фильтр, Москва 0 км, время, цена, год,
VIN либо внутренний идентификатор, НДС, ожидаемый статус. Затем сравнить с отчётом.

Приёмка успешна, если:

- ни одна ожидаемая активная машина не пропала из отчёта без причины;
- ID, страница, состояние прямой карточки и сведения совпадают с доказательствами;
- технический сбой не превращён в подтверждённый непоказ;
- сохранены оригинальная ссылка, снимок и время, включая снятые карточки;
- в AI-результате видны пропущенные задания, а не только успешные;
- новый запуск не использовал устаревшие файлы прошлого цикла;
- работа на MSI не приводит к устойчивому дефициту памяти и зависанию интерфейса.

Известные нарушения этих требований перечислены в [аудите](../analysis/AUDIT_2026-09-14.md).
Поэтому `MONITORING_SYSTEM_OK` сейчас недостаточен для окончательной приёмки.

## Замечания отдела продаж

Открыть «История и замечания» у машины либо «Обратная связь». Указать конкретное
поле, ожидаемое значение, ссылку и время проверки. Не писать просто «ошибка».
Ответственный сотрудник сверяет таблицу/площадку и подтверждает исправление.
Комментарий менеджера сам по себе не обучает веса LLM и не исправляет код.

Не отправлять полный внутренний отчёт на публичный GitHub Pages. Export допускает
только отдельную агрегированную страницу и требует свежий owner allowlist; процедура
в [M6 Operations](../production/OPERATIONS.md). Он не делает публичными VIN,
ссылки, карточки или внутренние замечания.
