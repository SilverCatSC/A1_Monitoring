# Состояние релиза A1 Search Monitor

Срез: 4 сентября 2026 года. Текущая версия: stage `0.2.0`.

## Проверено

### Данные

- Google Sheets CSV-export доступен и импортируется без marketplace API.
- Реальный снимок: 130 строк, 106 валидных, 24 диагностических.
- 34 автомобиля активны; распознано 78 Auto.ru и 76 Avito ссылок.
- Перестановка/неизвестные столбцы, алиасы, дубли и несколько VIN покрыты тестами.
- Резкое падение валидного снимка и критичный schema drift блокируют замену реестра.
- Управляемые фильтры `all_active` синхронизируются после импорта.

### Мониторинг

- Auto.ru parser адаптирован к текущим легковым и LCV путям.
- Avito parser имеет fixture-проверку известной структуры.
- Страницы 1–3, canonical marketplace ID, page/position и повторные эпизоды реализованы.
- CAPTCHA/429/неизвестная разметка/неполный проход дают technical, не absence.
- Первый валидный miss — uncertain; второй открывает confirmed episode.
- Scan и dealer discovery защищены от параллельного запуска.
- Скриншоты сохраняются в отдельный persistent volume с retention.

### Отчёт и люди

- HTML dashboard проверен в desktop browser.
- Видны KPI, operational status, импорты, фильтры, страницы/позиции, эпизоды,
  выходные, неполные ссылки, dealer-кандидаты и feedback.
- Текущие KPI исключают историю отключённых фильтров.
- Feedback lifecycle и append-only audit пройдены end-to-end на stage.
- Ручная правка ссылки валидируется и записывается в `ListingLinkEvent`.

### Эксплуатация

- Docker Compose поднимает app, PostgreSQL и ежедневный backup.
- Порты app/DB локально связаны только с `127.0.0.1`.
- Alembic `20260904_0003` применён к существующей stage-БД без потери реестра.
- Backup восстановлен в изолированную тестовую БД; контрольные количества совпали.
- Stage smoke проверяет readiness, импорт, status, dashboard, migration, порты,
  backup, restore и отсутствие traceback.
- Suite: 46 тестов; Ruff и `git diff --check` зелёные.
- Caddy cloud override подготовлен для HTTPS.

## Важная поправка к живым сетевым проверкам

Локальная машина в текущем сеансе работает через VPN. Поэтому:

- полученные Auto.ru кандидаты доказывают работу parser, но не production egress;
- Avito HTTP 429 ожидаем при VPN и не доказывает блокировку обычного cloud-IP;
- автоматический dealer discovery в локальном `.env` отключён;
- stage помечен `NETWORK_PROFILE=local_vpn`;
- production не стартует без явного `NETWORK_PROFILE=cloud_no_vpn`.

Ранее сделанный вывод о недоступности Avito с обычного облачного IP отменён как
неподтверждённый. Это должно быть проверено на целевом сервере без VPN.

## Открытые production-блокеры

1. Не предоставлены/не утверждены бизнес-URL фильтров; J:M исходного листа пусты.
2. Нет целевого VPS, домена и DNS, поэтому внешний HTTPS deploy не выполнен.
3. Не пройдена no-VPN проверка Auto.ru и Avito с production egress.
4. Не проведён 14-дневный пилот и ручная контрольная выборка.
5. Не настроен внешний канал уведомлений и список ответственных пользователей.
6. Требуется ротация обнаруженных ранее GitHub и DeepSeek credentials.
7. Требуется удалить публичное право записи на Drive-файл `SCRIPT.py`.

Пункты 1–3 требуют входных данных/инфраструктуры Owner и не могут быть корректно
«угаданы» кодом.

## Решение о готовности

Продуктовая кодовая база и локальный stage работоспособны; production не принят.
Следующий gate: целевой сервер без VPN + утверждённые фильтры, затем пилот.
