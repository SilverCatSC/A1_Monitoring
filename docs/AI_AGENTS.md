# Локальные AI-агенты A1 Monitoring

## Назначение

AI-контур дополняет, но не заменяет детерминированный мониторинг. Во время каждого
полного локального прогона он получает неизменяемый пакет: итог скана, результат
сверки ссылок, детерминированную сверку с головной таблицей, сохранённые тексты и
снимки карточек. Пакет разделяется на малые последовательные задания по одному
автомобилю, поэтому модель не держит весь реестр в одном огромном запросе.
Контур состоит из следующих стадий:

1. **Сверка головной таблицы** читает только лист `Размещение_автомобилей` таблицы
   `A1 АВТО // Digital // Размещение автомобилей`. По VIN, а при его отсутствии —
   по ID ссылки площадки и только затем по осторожному составному ключу, она
   сопоставляет цену, марку/модель, комплектацию, год и ссылки с реестром Monitoring
   с последней найденной карточкой выдачи и с последней прямой карточкой
   Auto.ru/Avito. Для прямой карточки проверяются состояние URL, цена, год, VIN,
   наличие и НДС; для Avito НДС извлекается из описания. Статус `Актуально` определяет,
   какие строки обязаны участвовать в контроле размещения. Источник не изменяется.
2. **Hermes Data QA** последовательно читает один малый пакет автомобиля и проверяет
   расхождения между источниками. Для этой рутинной стадии внутреннее рассуждение
   отключено; вывод ограничен коротким JSON.
3. **Hermes Vision** по одному анализирует сохранённые снимки поисковых и прямых карточек. Он извлекает
   видимые марку/модель, цену, продавца и статус, но не додумывает невидимое описание
   или галерею.
4. **Hermes Synthesis** получает только компактные результаты предыдущих стадий и
   использует ограниченное рассуждение для выбора пяти важнейших замечаний.
5. **Ouroboros** независимо проверяет покрытие, происхождение доказательств,
   противоречия и вывод Hermes, не повторяя распознавание каждой карточки. Он не
   получает доступ к браузеру или к таблицам, не меняет данные и формирует отдельное
   заключение для человека.

## Состав и изоляция

| Компонент | Версия / роль |
| --- | --- |
| llama.cpp | локальный сервер Metal на `127.0.0.1:18080` |
| Qwen3.5-9B Q4_K_M + mmproj-F16 | локальная GGUF-модель и vision-проектор, около 6,2 ГБ |
| Hermes Agent | QA и исполнитель инженерных задач |
| Q00/Ouroboros | организация проверяемого цикла разработки |
| Tirith | локальная проверка команд Hermes до исполнения, fail-closed |

Фиксация версий находится в `config/ai-tools.lock`. Локальные каталоги не входят
в Git:

- `artifacts/hermes_home` — профиль QA без инструментов;
- `artifacts/hermes_maintenance_home` — профиль обслуживания кода;
- `artifacts/hermes_ouroboros_llm_home` — внутренние текстовые проверки Ouroboros
  без инструментов;
- `artifacts/ouroboros_home` — конфигурация и журнал Ouroboros;
- `artifacts/ouroboros_worktrees` — изолированные рабочие копии;
- `artifacts/models` — веса и SHA-256;
- `artifacts/agent_work_units` — малые задания по автомобилям и их манифест;
- `artifacts/agent_reviews` — промежуточные и итоговые заключения QA.

В QA-профиле список инструментов пуст и отключён coding-контекст. В профиле
обслуживания нет браузерного и web-инструментария. Процессы получают очищенную
среду без ключей внешних LLM. У Ouroboros `llm.backend=hermes`, телеметрия
отключена одновременно в конфигурации и переменных среды. Cloud fallback у
Hermes отсутствует. У `llama-server` отключены Web UI и credentialed CORS; CORS
разрешён только для localhost. Рассуждение доступно, но применяется только к
компактной итоговой стадии и ограничено бюджетом. Инженерный профиль блокирует
команду, если локальный Tirith не смог её проверить.

## Ресурсный режим компьютера с 16 ГБ

- сервер использует не более четырёх основных и четырёх batch-потоков;
- одновременно выполняется один запрос и обрабатывается один снимок;
- batch/ubatch ограничены 256/128, длина ответа — 768 токенов, бюджет рассуждения — 256;
- между малыми заданиями по умолчанию выдерживается пауза 8 секунд;
- при техническом сбое или повреждённом JSON повторяется только неудачное малое
  задание, один раз; успешные этапы не запускаются заново;
- контекст остаётся 65 536 токенов, потому что Hermes не запускает модель с меньшим
  заявленным контекстом, но реальные малые запросы используют лишь нужную часть;
- процесс получает пониженный системный приоритет через `nice`.

Такой режим увеличивает продолжительность полного анализа, зато не создаёт пачку
параллельных запросов и не заставляет модель многократно рассуждать над всем реестром.
В полном цикле один загруженный сервер обслуживает Hermes и следующий за ним
Ouroboros, после чего выгружается; повторной загрузки весов между этими стадиями нет.
На основном Windows-ПК перед загрузкой модели служебный Chrome и Docker-контейнеры
останавливаются. Запуск блокируется при запасе RAM менее 7500 МБ.

```bash

./scripts/run_ouroboros_maintenance_macos.sh doctor install
```

Проверка Hermes на последнем уже сохранённом прогоне:

```bash
./scripts/run_ai_review_macos.sh
```

Результаты: `artifacts/agent_work_units/latest_manifest.json`, подробный
`artifacts/agent_reviews/staged_review_latest.json` и краткий
`artifacts/agent_reviews/latest.json`. В терминале видны стадии `AI_STAGE data`,
`AI_STAGE vision` и `AI_STAGE synthesis`. Если локальная модель или Hermes не
ответили, скрипт сохраняет частичную диагностику и не корректирует данные мониторинга.

Полный сценарий передаёт `cycle_id` сам. При ручном запуске `build_live_agent_packet.py`,
`run_ai_review_*` и `run_ouroboros_live_audit_*` обязаны получить один и тот же
завершённый `cycle_id`; сборка откажется от частичного цикла или смешанных
`latest`-артефактов.

## Реальный цикл

```text
импорт Monitoring
  -> сверка каталогов продавца
  -> поиск по фильтрам в видимом Chrome
  -> неизменяемые наблюдения и доказательства
  -> последовательное открытие прямых карточек и снимки их фактического состояния
  -> сверка активной таблицы маркетинга по VIN, ссылкам, статусу, цене и НДС
  -> сверка публичного каталога A1Auto.ru
  -> локальный Hermes QA
  -> независимый Ouroboros audit
  -> отдельные заключения для человека
```

CAPTCHA, 401/403/429, таймаут и неопределённость парсера остаются техническими
ошибками. LLM запрещено переименовывать их в «объявление не показывается». Система
сохраняет ограниченный фрагмент описания прямой карточки для проверки НДС
и статуса; полная галерея и полный набор опций пока не оцениваются. Карточка поиска
не является доказательством этих полей.
Отсутствующий снимок найденной карточки создаёт детерминированное замечание
`marketplace_card_evidence_missing` и требует повторной ручной проверки.

## Иерархия фактов и роль агентов

`Monitoring` — рабочее зеркало и история наблюдений, а не источник факта о наличии.
Ожидаемый состав задаёт таблица отдела маркетинга: статус `Актуально` означает, что
размещение должно быть проверено, в том числе для автомобиля «В пути» без VIN.
Кабинеты A1 Auto на Auto.ru (легковые и LCV) и кабинет Avito подтверждают состав
объявлений площадки; поиск по фильтру подтверждает видимость; каталог A1Auto.ru
подтверждает публикацию на собственном сайте. Эти факты не взаимозаменяемы.

Hermes получает последовательные части сохранённого пакета всех четырёх контуров,
объясняет подтверждённые расхождения и создаёт рекомендации для человека. Ouroboros
получает компактный результат и проверяет полноту покрытия, ограничения, происхождение
доказательств и качество рассуждения. Они могут формировать
предложения по правилам и тестам, но никогда не обучаются на одной ошибке, не меняют
ссылки, статусы, таблицу или код автоматически: предложение становится задачей только
после проверки человеком и регрессионных тестов.

## Инженерное обслуживание

Во время мониторинга Ouroboros работает только как read-only аудитор пакета. Для
инженерного обслуживания его задача должна содержать воспроизводимый дефект, критерии
приёмки и команду проверки. Рабочий результат остаётся в отдельном worktree; перенос,
commit, push и публикация не выполняются автоматически. На Mac с 16 ГБ используется
один worker: одновременный Chrome + Docker + большая контекстная модель могут вызвать
давление памяти.

Модель 9B полезна как дополнительный рецензент, но не является независимым
доказательством. Если у карточки отсутствует `card_evidence`, это отдельный пробел
доказательств, а не разрешение считать карточку подтверждённой. Критичные выводы
подтверждаются HTML/скриншотом, счётчиками и ручной выборкой. Эффективность оценивается на размеченном наборе: доля верных
замечаний, ложные тревоги, пропуски, время и пиковая память.
