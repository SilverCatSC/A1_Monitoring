# Контракт входных данных v1

## 1. Назначение

Контракт изолирует продукт от физической структуры таблицы подрядчика. Система читает заголовки и значения, преобразует их в каноническую модель и никогда не полагается на номера или буквы столбцов.

## 2. Канонические поля автомобиля

| Каноническое поле | Обязательность | Примеры заголовков | Правило |
|---|---:|---|---|
| `source_status` | Да | Статус | Определяет участие строки в импорте |
| `priority` | Нет | Приоритет | Нормализуется в справочник |
| `brand` | Да | Марка | Непустая строка |
| `model` | Желательно | Модель | Непустая строка |
| `brand_model` | Альтернатива | Марка, модель | Разделяется только по известному справочнику марок; неизвестное значение не угадывается |
| `vin` | Условно | VIN, VIN номер | Один VIN; составное значение отправляется на проверку |
| `price` | Нет | Стоимость, Цена | Число и валюта отдельно |
| `auto_ru_url` | Условно | Ссылка AUTO-RU, AUTO-RU | Допустимый URL Auto.ru |
| `avito_url` | Условно | Ссылка AVITO-RU, AVITO-RU | Допустимый URL Avito |
| `direct_url` | Условно | a1auto.ru, Ссылка A1Auto.ru | Прямая карточка автомобиля на сайте компании |
| `source_updated_at` | Нет | Дата обновления | Дата и время источника |

У автомобиля должна быть хотя бы одна прямая ссылка либо достаточный набор данных для ручного или автоматизированного обнаружения на странице дилера.

Статус `Актуально` в маркетинговой таблице — ожидание размещения. Он не требует
VIN: для машин «В пути» (например Maextro V800 или Mercedes VLE) первичный ключ —
ID ссылки Auto.ru/Avito либо путь карточки `a1auto.ru`; составное сопоставление
используется только как осторожная последняя возможность.

## 2.1 Поля головной таблицы для отчёта продаж

Последний read-only аудит головной таблицы сохраняет для активной строки:

- марку/модель и комплектацию;
- цену, год и пробег;
- VIN, если он уже присвоен;
- статус и наличие (`В наличии`, `В пути`, `Под заказ`);
- признак `с НДС`/`без НДС`;
- прямые ссылки Auto.ru, Avito и A1Auto.ru.

При отсутствии VIN устойчивый ключ строится по ID объявления, затем по карточке
A1Auto.ru и только в крайнем случае по составному набору полей. Номер строки не
считается устойчивым идентификатором. Из прямой карточки площадки сохраняется лишь
ограниченный доказательный набор: состояние URL, заголовок, цена, год, один VIN,
наличие, НДС и фрагмент описания. Для Avito отсутствие НДС в поисковом превью не
проверяется; требование применяется к описанию прямой карточки.

## 3. Что не является контрактом

- столбцы AD и AE;
- строки 2 или 3 как фиксированное начало данных;
- заметки ячеек как единственное место хранения URL;
- J, K, L и M как обязательные выходные столбцы;
- URL CSV-файла с изменяемым идентификатором;
- номер строки как идентификатор автомобиля.

## 4. Нормализация заголовков

Перед сопоставлением:

- удаляются пробелы по краям;
- повторяющиеся пробелы сворачиваются;
- регистр не учитывается;
- `ё` и `е` могут считаться эквивалентными;
- дефисы и подчёркивания нормализуются;
- известные алиасы задаются конфигурацией;
- точное совпадение имеет приоритет над алиасом.

Нечёткое семантическое угадывание критических полей не применяется автоматически.

## 5. Статусы импорта

- `ACCEPTED` — снимок полностью прошёл проверку.
- `ACCEPTED_WITH_WARNINGS` — есть некритические замечания.
- `QUARANTINED_SCHEMA` — схема неизвестна или неоднозначна.
- `QUARANTINED_DATA` — обнаружены критические ошибки строк.
- `FAILED_TECHNICAL` — источник нельзя получить.

Только первые два статуса могут создать новую активную версию реестра.

## 6. Проверки строк

- одна строка описывает один автомобиль;
- два VIN в одной ячейке запрещены;
- пустой VIN допускается только с предупреждением и другими идентификаторами;
- повтор VIN не объединяется автоматически;
- URL проверяется по домену и извлекаемому ID объявления;
- две строки с одним `listing_id` помещаются на проверку;
- неизвестный бизнес-статус строки не активируется молча;
- цена не подменяется нулём при ошибке разбора.

## 7. Версионирование

Для каждого принятого импорта сохраняются:

- `import_id`;
- время получения;
- ID таблицы и листа;
- список исходных заголовков;
- версия mapping;
- checksum снимка;
- количество принятых, предупреждённых и отклонённых строк;
- ссылка на предыдущую активную версию;
- автор ручного подтверждения, если оно было.

## 8. Поведение при изменении таблицы

| Изменение | Поведение |
|---|---|
| Переставлены столбцы | Автоматически принять |
| Добавлен необязательный столбец | Принять с записью изменения |
| Известный заголовок переименован в известный алиас | Автоматически принять |
| Исчезло критическое поле | Карантин, уведомление |
| Появились два кандидата на одно поле | Карантин, ручной выбор |
| Изменился тип данных | Карантин строк или снимка по критичности |
| Изменился смысл бизнес-статуса | Требуется новая версия правила |

## 9. Фильтры

Фильтры хранятся отдельно и связываются с автомобилями отношением
многие-ко-многим. Канонический каталог может назначать связь по явному,
версионированному правилу площадки, семейства модели и состояния, используя
валидную прямую ссылку объявления. Нельзя создавать поисковый URL эвристически
или назначать неизвестную модель «ближайшему» фильтру.

Минимальные поля фильтра:

- `filter_id`;
- площадка;
- понятное название;
- URL;
- версия;
- активный период;
- ожидаемый тип транспорта;
- часовой пояс;
- список назначенных автомобилей;
- автор и основание изменения.
