# Учёт изменений кода

Источники правды: Git для изменений файлов, CHANGELOG.md для поведения продукта,
Alembic для структуры БД, tests для проверяемых контрактов. Журнал событий в Web
относится к работе программы и реестру, а не заменяет Git.

Каждый релиз:

1. Проверить git status; отличить существующие изменения от новой задачи.
2. Описать причину и эффект в CHANGELOG, обновить документацию метрик при изменении формул.
3. При изменении схемы добавить миграцию и проверить обновление существующей БД.
4. Выполнить make check, make doctor и визуальную проверку экранов.
5. Зафиксировать commit/tag после согласования. Не включать .env, VIN-выгрузки,
   Chrome-профили, скриншоты, артефакты, дампы или токены в Git.

На момент начала 0.7.0 рабочее дерево уже содержало изменения от предыдущих
доработок. Они сохранены. Автоматический git add/commit/push не настроен: он мог
бы включить посторонние изменения. Для просмотра используйте git diff и git log.
Новые файлы проверяйте отдельно через git status --short.

## Целевой режим автономных исправлений

По уточнению владельца 09.09.2026 агентам разрешён доступ к проекту. В целевом
режиме исправления, сохраняющие бизнес-контракты и схему БД, смогут автоматически
проходить тестирование и переключение релиза между циклами без согласования каждой
правки. Для этого сначала реализуются изоляция рабочей версии, проверка регрессий,
журнал изменений и восстановление. Эти механизмы пока не включены; ручной порядок
выше описывает текущую версию. Детали: [MSI_AGENT_PUBLICATION_PLAN.md](archive/MSI_AGENT_PUBLICATION_PLAN.md).
