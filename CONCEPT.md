# Концепция A1 Search Monitor v1.1 (No-API)

## 1. Проблема

Текущая цепочка из Google Apps Script + локальных скриптов даёт нестабильный контроль:
- зависит от структуры конкретной таблицы подрядчика,
- зависит от локального ПК,
- неразделяет технические сбои и бизнес-показатели.

Нужна система, которая даёт управляемый и повторяемый мониторинг видимости объявлений без API площадок.

## 2. Продуктовое решение

Система преобразуется в сервис, который:

1. Импортирует объяв. и фильтры из источника подрядчика (CSV/XLSX/экспорт).
2. Обновляет реестр и хранит версионную историю импорта.
3. Ежечасно/периодически прогоняет выдачи фильтров на первых 3 страницах.
4. Сохраняет наблюдения в историю и строит эпизоды отсутствия.
5. Показывает отчёты и даёт канал обратной связи менеджеров.

## 3. Что является бизнес-истиной

- На что и где объявление действительно попадает в выдаче при конкретном фильтре.
- Где есть технический пробел, а где подтверждённый факт непоказа.
- Сколько и какие эпизоды отсутствия стартовали (в т.ч. на выходных).

## 4. Ключевые сущности

- **Vehicle** — внутренний автомобиль.
- **Listing** — конкретное объявление с привязкой к площадке и listing_id.
- **SearchFilter** — URL-фильтр + платформа + метаданные.
- **Expectation** — связь объявления и фильтра.
- **ListingObservation** — факт по паре `объявление + фильтр + цикл`.
- **AbsenceEpisode** — подтверждённый интервал непоказа.
- **SourceImportSnapshot** — контрольный снимок источника.
- **ManagerFeedback** — замечания людей верификации.

## 5. Правила приоритетов статусов

1. `FOUND_PAGE_1/2/3` — приоритетно и подтверждаемо фактами выдачи.
2. `ABSENT_CONFIRMED` — только при полной валидной проверке страниц 1–3.
3. `TECHNICAL/UNCERTAIN` — никогда не закрывают историю непоказа как факт.
4. Любой технический статус должен быть прозрачно виден в KPI-сводке.

## 6. Режим работы по таблице подрядчика

Система должна выдерживать:
- перестановку колонок,
- дополнительные незначимые колонки,
- переименование в рамках известных алиасов.

Критический дрейф структуры => карантинный импорт и сохранение старой рабочей версии.

## 7. Выходные

Рабочая логика одинакова 7/7.  
Отдельно считаются эпизоды и пробелы, которые затрагивали субботу/воскресенье.

## 8. Успех проекта v1

Успех достигается не «красивой картинкой», а воспроизводимостью:
- отсутствует ложный непоказ при технических сбоях,
- все изменения структуры таблицы управляются через snapshot + quarantine,
- отчёты всегда показывают, что из фактов, что из технического шума.

## 9. Что остаётся за рамками v1

- автоматический «починок» объявлений;
- предсказание алгоритмов площадок;
- управление рекламными ставками;
- обход/хаки API и обход блокировок.
